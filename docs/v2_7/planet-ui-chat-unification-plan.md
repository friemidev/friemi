# v2.7 星球 UI 与群聊统一改造方案

更新时间：2026-08-13  
实施分支：`ui/v2-7-planet-ui-adjustments`

## 1. 需求结论

本轮将截图中的三层页面重新收束为两类主要体验：

1. **星球详情页**：保留星球资料，并直接承载历史精彩瞬间、照片墙、弹幕、点赞、评论及发布入口。
2. **星球群聊页**：从星球详情中拆出，改为独立全屏聊天页面。
3. **世界 > 聊聊**：统一展示私聊、聚吧群聊和星球群聊，成为所有聊天室的集中入口。

第三张页面中的功能不删除，只迁移到第二张星球详情页。原第三张路由保留兼容跳转，避免旧链接失效。

## 2. 当前实现核对

### 当前页面关系

| 截图/页面 | 当前路由 | 当前内容 |
| --- | --- | --- |
| 第一张：星球入口 | `/planets`、`/footprints?tab=planet` | 星球列表、创建星球 |
| 第二张：星球详情 | `/planets/[planetSlug]` | 星球信息、轨迹缩略图、内嵌聊天室、消息输入、发布精彩瞬间 |
| 第三张：精彩瞬间 | `/planets/[planetSlug]/moments/[momentId]` | 照片轮播、弹幕、点赞、评论输入、删除 |
| 世界聊聊 | `/footprints?tab=message` | 私聊、聚吧群聊及筛选器 |

### 当前数据边界

- 星球聊天使用 `PlanetMessage`。
- 聚吧群聊使用 `ActivityRoomMessage`。
- 私聊使用 `DirectMessage`。
- 星球聊天目前没有独立的已读、未读、勿扰和置顶状态。
- 世界聊聊目前只聚合私聊和聚吧群聊。
- `getPlanetRoom()` 会在星球详情页读取最多 40 条聊天消息；聊天室拆出后，这部分查询应从详情页移除。
- 星球详情只读取精彩瞬间摘要，第三张页面才读取完整照片、点赞和弹幕数据。

## 4. 星球详情页方案

### 4.1 顶部区域

保留：

- 返回星球广场。
- 星球头像、名称和成员数。
- 加入、等待审核、退出等成员状态。
- 创建人管理入口及待审核成员入口。

新增：

- 在顶部信息下方增加主按钮 **“前往群聊”**。
- 已有未读消息时显示数字角标；开启勿扰后只显示红点。
- 已审核成员可直接进入群聊。
- 待审核成员显示“审核通过后可群聊”，不得进入或读取消息。
- 未加入用户点击时进入现有申请加入流程，不暴露聊天内容。

### 4.2 历史精彩瞬间区域

原聊天室区域替换为完整的精彩瞬间内容：

1. 顶部保留横向“星球轨迹”选择器，按时间倒序排列。
2. 默认展示最新一条精彩瞬间。
3. 点击轨迹后在当前页面切换内容，不再跳到第三张页面。
4. 当前瞬间展示完整照片轮播，保留左右滑动、页码和自动轮播。
5. 弹幕继续浮动展示在照片区域上方。
6. 保留正文、作者、发布时间、点赞数量和点赞操作。
7. 保留弹幕/评论输入；只有审核通过的成员可以发送。
8. 保留作者删除精彩瞬间的权限。
9. 星球创建人保留“发布精彩瞬间”入口。
10. 没有历史内容时展示清爽空状态，并给有权限的创建人发布入口。

### 4.3 页面状态与深链接

- 推荐使用 `/planets/[planetSlug]?moment=[momentId]` 表示当前选中的精彩瞬间。
- 浏览器前进、后退应恢复选中的瞬间。
- 原 `/planets/[planetSlug]/moments/[momentId]` 不立即删除，应重定向到新地址。
- 分享旧链接、收藏链接和通知链接仍能准确定位到同一条内容。
- 如果目标瞬间已删除，回到该星球最新一条瞬间并给出简短提示。

### 4.4 组件调整

- 将 `PlanetRoomComposer` 拆分为：
  - `PlanetMomentComposer`：留在星球详情页。
  - `PlanetChatComposer`：移动到独立星球群聊页。
- 将第三张页面的 `PlanetMomentCarousel`、点赞和弹幕输入组合成可嵌入详情页的内容模块。
- 不在星球详情页加载聊天消息，避免无意义的 40 条消息查询。

## 5. 独立星球群聊方案

### 5.1 路由

新增：

```text
/planets/[planetSlug]/chat
```

### 5.2 页面布局

- 使用全屏聊天页面，不使用嵌套半屏弹窗。
- 顶部只显示返回、星球头像/名称和更多菜单，不重复显示“星球群聊”眉标题。
- 消息区独立滚动，输入区固定在底部并适配安全区域和键盘。
- 时间按照现有聊天规则使用时间分隔线，不为每条消息重复显示时间。
- 从星球详情进入时，返回恢复星球详情。
- 从世界聊聊进入时，返回恢复 `/footprints?tab=message` 及原筛选和滚动位置。
- 直接打开聊天 URL 时，返回兜底为世界聊聊。

### 5.3 权限

- 只有 `APPROVED` 的星球成员能够读取和发送消息。
- `PENDING`、已退出、被拒绝和非成员不能通过直接 URL 绕过权限。
- 创建人和管理员沿用现有成员审核权限。
- 星球退出后立即从世界聊聊列表移除，并禁止继续访问聊天页。

### 5.4 聊天设置

为了真正接入统一聊聊管理，星球群聊需要支持：

- 已读时间。
- 未读数量。
- 消息免打扰，默认关闭。
- 置顶聊天，默认关闭。
- 勿扰时有新消息只显示红点，不计入聊聊数字角标。
- 置顶后在世界聊聊顶部使用与现有置顶聊天一致的浅灰背景。

本轮不要求把三种消息合并进同一数据库表。统一的是入口、列表、状态规则和视觉体验，保留各自业务表可以降低迁移风险。

## 6. 世界“聊聊”接入方案

### 6.1 列表聚合

`FootprintsMessageList` 从两类会话扩展到三类：

```text
direct      私聊
activity    聚吧群聊
planet      星球群聊
```

统一排序规则：

1. 置顶会话优先。
2. 同为置顶或非置顶时，按最后一条消息时间倒序。
3. 没有消息的已加入星球群聊使用加入时间排序。
4. 稳定使用会话种类和 ID 兜底，防止列表跳动。

### 6.2 筛选器

保留当前筛选：

- 聊聊：全部有内容或已置顶的会话。
- 群聊：同时包含聚吧群聊和星球群聊。
- 互相关注：仅私聊。
- 我关注的：仅私聊。
- 官方：仅官方账号私聊。

星球群聊不新增顶层筛选按钮，避免筛选条继续变长。群聊列表中通过头像和小型“星球”标识区分聚吧与星球。

### 6.3 星球群聊列表项

- 使用星球封面作为圆角方形头像，无封面时使用星球图标。
- 展示星球名称、最后发送者、消息摘要和时间。
- 未读规则与聚吧群聊一致。
- 支持搜索星球名称、标签、最后消息和最后发送者。
- 已审核但尚无消息的星球，在“群聊”筛选下仍可看到，摘要显示“还没有消息”。
- 退出星球或成员权限被移除后，不继续展示历史入口。

### 6.4 全局角标

- `/api/navigation/unread-counts` 增加星球群聊未读数。
- 总聊聊未读数为：私聊 + 聚吧群聊 + 星球群聊。
- 勿扰会话不计入数字总数，但列表内保留红点。
- 进入星球群聊并成功读取消息后，列表和底部导航角标同步清除。
- 接口失败时保留最后一次有效角标，不错误显示为零。

## 7. 数据与查询方案

### 7.1 新增星球聊天读取状态

建议新增独立模型 `PlanetChatReadState`，核心字段：

```text
planetId
profileId
lastReadAt
mutedAt   nullable
pinnedAt  nullable
createdAt
updatedAt
```

约束与索引：

- `@@unique([planetId, profileId])`
- 按 `profileId + pinnedAt + updatedAt` 支持聊聊列表。
- 按 `planetId + profileId` 支持已读和设置更新。
- 与 `Planet`、`UserProfile` 使用级联删除，避免退出或删除星球后留下无效状态。

实现采用可空时间戳而不是布尔字段：`null` 表示关闭，非空值同时表达开启状态和操作时间，便于后续稳定排序、审计和迁移。

### 7.2 查询拆分

避免把所有功能塞进一个大查询：

- `getPlanetOverview()`：星球资料、成员状态、轨迹摘要。
- `getPlanetMomentPanel()`：只读取当前选中瞬间的完整照片、点赞和分页评论。
- `getPlanetChatPageData()`：读取最近一页聊天消息，后续用 cursor 增量加载。
- `getPlanetChatRoster()`：只返回世界聊聊所需的会话摘要，不读取完整聊天历史。
- `getPlanetChatUnreadCount()`：接入全局角标聚合。

评论和聊天消息都必须设置 `take`/cursor 上限，不能随着历史增长一次性加载全部记录。

### 7.3 数据兼容

- 现有 `PlanetMessage`、`PlanetMoment`、评论和点赞数据全部保留。
- 不迁移或复制现有聊天正文。
- 新读取状态可以按用户首次进入聊天时懒创建。
- 上线前后星球历史消息和精彩瞬间数量必须一致。

## 9. 预期效果

### 用户体验

- 用户进入星球后，首先看到星球历史和照片内容，不再被聊天室占据主要页面。
- 查看照片、弹幕和历史时不需要反复进入第三层页面。
- 所有聊天入口集中到世界聊聊，不需要记住不同模块的聊天室位置。
- 星球详情仍保留明确的“前往群聊”快捷入口，不增加寻找成本。
- 私聊、聚吧群聊和星球群聊拥有一致的未读、勿扰和置顶体验。

### 技术效果

- 星球详情不再加载聊天历史，减少与详情无关的数据库读取；响应体改为承载当前精彩瞬间，不承诺 HTML 体积一定下降。
- 聊聊列表只读取星球聊天摘要，不读取完整消息。
- 三种聊天保留独立领域模型，降低高风险数据迁移和权限串线风险。
- 旧精彩瞬间链接继续有效，不影响已分享内容。

### 产品边界

- 本轮统一“聊天室入口和管理体验”，不强行统一三种消息表。
- 本轮不新增语音、视频、文件消息或复杂实时协议。
- 本轮不改变星球加入审核规则和精彩瞬间发布权限。
- 后续若统一实时传输，可以在保留三种业务表的前提下建立统一事件协议。

## 10. 风险与保护措施

| 风险 | 等级 | 影响 | 保护措施 |
| --- | --- | --- | --- |
| 非成员通过聊天 URL 读取消息 | 高 | 星球隐私泄露 | 服务端每次读取和发送都校验 `APPROVED`，不能只依赖按钮隐藏 |
| 未读数加入全局角标后计算错误 | 中 | 数字重复、漏算或勿扰仍计数 | 独立 read state、旧值对照测试、勿扰规则单测 |
| 世界页面新增 roster 查询增加负载 | 中 | 世界标签加载变慢 | 只读摘要、设置上限、按标签懒加载，不读取消息列表 |
| 第三张页面移除导致旧链接 404 | 中 | 已分享内容打不开 | 保留兼容路由并重定向到 `?moment=` 深链接 |
| 页面内切换瞬间加载全部评论 | 中 | 历史多时响应变慢 | 只加载当前瞬间，评论 cursor 分页 |
| 返回路径丢失 | 中 | 从聊聊返回错误页面 | 使用历史返回并设置直接访问兜底路径，保存列表筛选和滚动位置 |
| Prisma migration 未部署 | 中 | 聊聊页面运行时报表不存在 | 本地、Preview 依次 `migrate deploy` 并运行 schema 验证 |
| 迁移后 UI 内容过密 | 低 | 星球详情显得混乱 | 轨迹选择、当前内容和操作按固定层级排布，避免卡片套卡片 |

## 11. 回滚方案

- P1、P2、P3 分开提交，禁止一次提交同时改详情、路由、未读和世界列表。
- 新聊天路由未稳定前，旧内嵌聊天室可由临时功能开关恢复。
- `PlanetChatReadState` 是附加表，回滚 UI 时不影响现有 `PlanetMessage` 数据。
- 旧精彩瞬间路由在完整验收前始终保留。
- 全局角标异常时，可以暂时停止汇总星球未读，不影响聊天消息本身。

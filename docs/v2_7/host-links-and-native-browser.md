# 主理人链接与原生浏览器

## 业务行为

- 普通聚吧详情的手机布局在报名或取消报名按钮下方展示主理人链接，桌面沿用现有详情区域。
- 创建及编辑聚吧可选择补充登记、活动资料、线下预约/购票或其他内容。兼容已有 `RESERVE_SPOT`、`VIEW_DETAILS` 和自定义文字，保存到现有 `ticketUrl`、`ticketLabel` 字段，不增加数据库迁移。
- 展示真实来源域名，发布时仅接受无用户名、密码的 HTTPS 地址。不把 Google 表单域名等同于可信内容，仍使用现有聚吧举报、管理和下架流程。
- 补充登记、资料及其他内容在聚吧结束后仍可访问；预约/购票在已结束或已取消时关闭。
- 打开、返回或关闭第三方页面不更新 Friemi 的报名、预约或支付状态。外部表单提交结果不自动视为 Friemi 报名成功。
- 主理人仍需遵守活动与内容政策，不得通过本入口绕过应用内数字权益的商店付费规则。

## 打开与返回

- 网页使用真实 `target="_blank"` 链接，保留原聚吧页面。
- 新版 Android 调用 `FriemiAndroid.openHostLink`，通过 Custom Tabs 打开；关闭或系统返回后原 WebView 的地址、登录和滚动保持不变。
- 新版 iOS 先查询 `FriemiNavigation.getExternalBrowserSupport`，再调用 `openHostLink`，以 SFSafariViewController 展示第三方内容。关闭仅 dismiss 原生浏览器，不重载 Friemi。
- 内嵌详情页仅与主页面交换同源消息。主页面检查 origin、对应 iframe 和当前可见状态后才能执行打开请求。第三方网页不接入 Friemi 原生桥，也不接收 Friemi 登录凭据。
- 老安装包缺少能力查询或新方法时走原有外部浏览器打开流程，不显示技术异常。新方法临时失败后显示简短错误，再次点击使用普通浏览器链接。

## 发布顺序

1. 部署网页代码，旧包可以使用新入口和普通浏览器兜底。
2. Android 开发人员从包含本次修改的分支构建新 AAB 并提交；本次 Java 调试编译检查不生成商店发布包。
3. iOS 开发人员从同一分支用 Xcode 构建、TestFlight 验证再提交。修改在既有 `FriemiNavigationPlugin.swift` 中，未增加 CocoaPods 依赖。
4. 两端真机验收后再确认原生浏览器体验已经对相应版本生效。网页更新不能给旧包补充原生方法。

## 验收清单

- 未报名、已报名、主理人、游客四类状态均能找到合适入口；打开后不改变参与状态或人数。
- 三语种、窄手机和桌面没有按钮文字换行、溢出或主按钮冲突。
- 直接打开详情以及从首页打开嵌入详情均可调用新浏览器；外链关闭后仍在原聚吧。
- 连续点击不重复打开；错误可重试；旧包不出现插件未实现报错。
- 补充表单在已结束聚吧仍显示，预约/购票在已结束或已取消聚吧不显示。
- Android 返回键和 iOS 关闭、向下拖动可返回，第三方登录、表单键盘和必要的浏览器菜单正常。
- 非对应 iframe、异源消息、不安全网址及隐藏详情页不能请求主页面打开链接。

本地样例只使用专用 PostgreSQL 55433：在已有本地预览数据的工作树中运行 `node apps/web/scripts/seed-host-link-preview.mjs`。禁止对预览云数据库或生产数据库运行此脚本。

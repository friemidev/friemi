# 你画我猜 P1 实施与验收记录

更新于 2026-09-28。P1 的存储、举报、异常提示和运维接口已在本地实现，并在隔离的画猜 Preview 完成真实 Clerk 多会话验证。扫描故障能触发 GitHub 监控失败并向现有收件箱发出邮件，真实管理员审核、保留期清理与压缩后作品读取也已实测。P1 的测试环境功能验收已闭环；是否开放长期灰度仍取决于正式环境的容量预算和真机弱网体验。

## 本次实现

1. **作品与命令持久化**：接龙作品和草稿存入 `DrawGuessArtwork`，以房间、局号、链作者座位和棒次唯一标识；笔画 JSON 与服务器生成的 PNG 同存于私有 PostgreSQL 表。PNG 上限 512 KB，仅已结束局的房间成员可通过鉴权 API 读取。命令去重结果存入 `DrawGuessCommand`，房间快照中的作品笔画、草稿和命令结果清空；读取本人房间快照与往期作品时从记录恢复。旧格式房间在下一次写入时迁移原有作品与命令结果。
2. **内容与举报**：手动词限制为可见文字，拒绝链接、长数字、控制字符与内置阻断词片段；房间揭晓后可举报词或画。举报按成员、作品和局号唯一，单用户每小时最多 10 条；审核人员可通过管理员 API 查询并标记“已审/驳回”，结果不影响既有投票或分数。
3. **通知与失败提示**：房间订阅成功后重新获取本人服务端快照；Broadcast 不可用时继续 2 秒轮询，并明确说明画笔不会实时传输。补登录失效、人数不足、阶段结束、暂停新局、草稿保存失败和超时推进提示。
4. **运维边界**：接龙新局默认关闭，`DRAW_GUESS_CHAIN_ENABLED=true` 才允许新房间、开局与再来一局，已在进行的局仍可完成。管理员健康接口提供活跃/逾期房间数、待审举报数、作品表和数据库字节数，以及 Realtime 环境变量就绪状态。公共健康接口检查 5 秒扫描、逾期房间、举报积压和作品表占用；作品表默认达到 256 MiB 时返回 503，可通过 `DRAW_GUESS_ARTWORK_WARN_BYTES` 调整。阶段推进、重复命令、预览生成与持久化失败写结构化日志；截止扫描有错误或积压时报警日志。部署后每日运行维护任务：命令结果保留 30 天，已归档局的未提交草稿保留 7 天，即使同一房间已开始下一局也会清理；已结束房间和作品最多保留 365 天，未处理举报阻止房间清理。

## 本地证据

- 隔离 PostgreSQL 17 上 72 个迁移全部成功，未修改远端或生产数据库。
- P0 的 5、6、7、8 人完整接龙、并发与唯一结算回归通过。
- P1 集成脚本验证：房间快照无笔画/命令累积、草稿恢复、PNG 签名与大小、未揭晓拒读、成员授权读取、旧局作品恢复、旧格式房间再来一局时的作品迁移、举报去重/权限/并发配额、审核、暂停开局、保留期清理与未结举报保护。
- 本地 Next 页面验证：维护任务无凭证返回 401、携带本地密钥返回 200；手机 390 px 和桌面 1280 px 的房间及历史页无横向溢出、图片无破损、举报表单成功提交，控制台无错误或警告。截图保存在本地 `output/playwright/draw-guess-p1-*.png`。
- 复核时补充：房间轮询以修订号返回 304，只有变化或截止时间到期才从作品表恢复笔画；恢复查询不会读取 PNG 二进制。隔离数据库验证已归档局草稿的 7 天清理与当前局草稿保留。本机现有 Supabase 测试配置可订阅随机临时频道，服务端广播返回 202 且订阅者确实收到事件；此结果不是 Preview 真实房间验收。
- 画猜分支已生成独立 Ready Preview；对比 Vercel Preview 与 Production 的数据库项目标识后，向隔离的 Preview 库应用 3 个画猜迁移，状态为 72 个迁移全部最新。仅对画猜分支的 Preview 设置 `DRAW_GUESS_CHAIN_ENABLED=true`，新部署已生效。Preview Supabase Cron 的 5 秒任务连续成功，Vault 鉴权请求收到 200；5 人临时房间在全员离线时自动跨阶段，Preview 服务的 Supabase Broadcast 到达订阅者，测试数据已清除。每日维护任务也在 Preview 数据库中激活，手动调用 Preview 维护 API 返回 200。Vercel 自带 Cron [只运行于 Production](https://vercel.com/docs/cron-jobs/quickstart)，因此 Preview 维护由 Supabase Cron 调用。
- Preview 中使用 5、6、7、8 个独立 Clerk 会话分别完成全流程对局、投票、作者选画、旧局查看和再来一局。新会话恢复草稿、房主失联接替、房间成员才能读取旧局 PNG、非成员和匿名访问被拒，均已验证。成员举报成功；重复举报与非成员举报被拒；普通成员访问管理员健康接口得到 403。页面连接到了 Preview Supabase Realtime WebSocket，重连提示在连接恢复后消失。7 个测试房间、8 个资料及 8 个临时 Clerk 账号均已清理。
- Preview 的 `/api/health` 已把逾期房间、待审举报数量、5 秒截止任务最近成功时间和任务启用状态纳入健康判断；健康时返回 200，异常时返回 503。GitHub `Site Monitoring` 已重新启用并指向画猜 Preview，首次正常运行成功：[运行 #21](https://github.com/friemidev/friemi/actions/runs/36438042536)。短暂停用 Preview 扫描后，[运行 #22](https://github.com/friemidev/friemi/actions/runs/36438779487) 只因健康接口 503 失败，失败邮件到达 TiantianTitan 的收件箱。扫描已恢复 Active、最近运行 succeeded，健康接口回到 200；同一运行重跑显示 Success。作品占用告警部署后，[运行 #23](https://github.com/friemidev/friemi/actions/runs/36441210574) 再次通过。将本地作品占用阈值临时设为 1 字节时，健康接口返回 503；使用默认 256 MiB 时返回 200。
- Preview 中创建一个临时 Clerk 管理员身份与一条测试举报：管理员健康接口和待审列表均返回 200，`openReports=1`；审核 POST 返回 200，数据库状态变为 `REVIEWED`。临时账号、房间、24 张测试作品和举报均已删除。随后在 Preview 造 366 天前的两个已结束房间，运行实际维护函数，结果为 `commandsDeleted=1`、`draftsDeleted=1`、`roomsDeleted=1`；有未处理举报的房间与当前局草稿保留。测试记录已清理。
- 高细节合成画作使用 80 笔、2000 个点，JSON 26,881 字节。原 PNG 每张 266,520 字节，8 人一局 24 张作品的 PNG 共 6,396,480 字节；成员读取 20 次的 p50 为 808 毫秒、p95 为 919 毫秒。新版 128 色 PNG 在 Preview 每张 58,977 字节，24 张共 1,415,448 字节；画作 JSON 列共 314,952 字节。成员鉴权读取 20 次的 p50 为 765 毫秒、p95 为 798 毫秒。PNG 约减少 78%；同尺寸压缩前后图像已人工对比。该样本是压力型合成图，不能代表真实玩家平均画作，单次延迟测量也不能作为网络 SLA。

## 部署前仍需完成

1. 结合真实玩家画作分布、365 天保留期和实际数据库磁盘余量确定灰度房间数与留存方案。2026-09-28 已核实 Supabase 组织为 Pro，Preview 为 nano、Production 为 micro，两个数据库均位于 `eu-west-1`；先前基于 Free 500 MB 的预算假设不适用。以本次压缩后高细节样本估算，8 人一局 24 张画作的 PNG 加 JSON 约 1.73 MB（不含行与索引开销），10 局/天连续 365 天约 6.3 GB；需以正式项目的实际磁盘额度和其他业务增长核定留存，不能以 Preview 成功代替正式预算。
2. 先前浏览器工具输出曾显示现用的 `CRON_SECRET`；Vercel 项目设置已确认它是作用于 Production 与 Preview 的同一配置变量，且界面标为 `Needs Attention`。灰度前需在已确认维护窗口和接收方后同步轮换 Vercel 密钥与 Preview Supabase Vault 中的值，再复测两个定时入口的鉴权和 5 秒扫描。文档不保存任何密钥值；未取得这项变更的确认前不触碰正式环境。
3. 真机弱网和后台切换体验，以及发布开关回滚演练可在灰度前补齐。当前的 5–8 人对局使用独立浏览器会话和同机浏览器测试，并非 8 台物理设备。正式数据库迁移与监控目标切换仍属于发布流程。

P1 达标后才可把接龙模式小范围灰度；普通抢猜的画笔实时性仍按 P2、P3 验收。

# 斗地主功能闭环与 UI 审计

日期：2026-10-16。分支：`二游`。审计基线：`8bf49032`，修复包含在本报告所在提交。

## 结论

以「三位好友建房、按约定局数娱乐计分」为产品范围，修复后的功能已形成完整开发闭环：创建/加入 → 设置 → 准备 → 叫分/出牌 → 单局结算 → 累计与下一局 → 整场结果 → 再开一场或关闭 → 查看历史。恢复、离席托管、错误重试和账号隔离也有对应处理。

这不等同于已经达到成熟线上产品的发布验收标准。当前通过了本地规则、真实 PostgreSQL、浏览器交互和模拟网络异常验证；真实三账号联网、Supabase 私有频道、独立到期 worker、iOS/Android/WebView 和实际音频听感仍待独立验收。没有用本机三席预览替代这些证据。

| P2 | 关房、权限失效后的本地「继续」入口可能残留 | 按游戏种类、房间及账号精准清理；不会删除其他房间/账号；停掉已失权房间的轮询和订阅 |

## UI 判断

当前牌桌可以继续沿用 Friemi 的浅蓝桌面、暖白牌和猫角色。核心信息顺序明确：轮次/计时与底牌、对手公开信息、当轮出牌、操作按钮、自己的手牌。此前移除的「选中几张」和重复牌型文字没有重新加回。

本轮针对实际操作优化：入口突出创建或恢复的主操作；大厅把设置、记分板、历史放在同一组，关闭房间保留在次要位置；离线状态与未准备分开；历史显示本地日期和时间、各人分数、叫分/倍数/炸弹/春天；通用弹窗补齐三语关闭标签和焦点管理。英法长标签可以换行，大厅允许纵向滚动，牌桌保留横屏约束。

后续 UI 优化应由设备体验决定：17/20 张叠牌的实际误触率、小屏安全区、声音开关与展开手牌的可达性，以及猫动作和语音在整局中的疲劳感。先做三位真人完整局测试，再决定是否调整牌间距、动画时长和素材，当前不继续无依据地改视觉风格。

## 发布前尚需完成

1. 三个独立真实账号/设备：建房邀请、并发点击、换座、断网重连、离席回来、完整多局和关闭后个人历史。
2. 测试部署：迁移、Clerk 与 Supabase 私有频道授权/失效、独立 deadline worker 全员离线仍推进、服务异常日志及持续运行。并发/负载测试尚未做，不宣称已具备高并发稳定性。
3. iOS Safari、Android Chrome 与两端 WebView：方向锁支持情况、安全区、触控、后台恢复、音频解锁、实际听感和卡顿。
4. 全站跨游戏占位：斗地主账号锁已实现，但旧 UNO 等服务尚未统一遵循同一锁约定，仍有跨游戏同时开局的待处理范围，不能宣称已全站互斥。

这些项是明确的剩余验收/集成工作。当前没有执行线上发布、迁移远端数据库或修改其他游戏服务。

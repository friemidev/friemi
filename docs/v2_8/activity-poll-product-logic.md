# 聚吧投票 v2.8：Doodle 参考逻辑与 Friemi 产品方案

> 文档状态：产品逻辑草案（Draft，待产品确认）
> 更新日期：2026-09-18
> 参考对象：Doodle Group Poll 当前公开产品与官方帮助中心
> 目标：在聚吧内提供轻量投票，并支持通过链接分享给站外用户；创建者可以决定游客是否能投票，游客投票时必须填写昵称。

## 0. 结论先行

Friemi 投票不是一个脱离聚吧的独立问卷系统，而是聚吧协作工具。每个投票必须属于一个真实聚吧，投票创建者必须是已登录且有管理权限的用户；参与者可以是聚吧成员、通过链接进入的登录用户，或创建者明确允许的游客。

v2.8 采用 Doodle 已验证的低门槛参与骨架：

```text
创建投票
-> 填写问题和选项
-> 设置截止时间与参与规则
-> 在聚吧内发布
-> 可复制链接分享至站外
-> 参与者无需注册也可完成投票（仅在创建者允许时）
-> 投票关闭前可修改自己的选择
-> 创建者关闭投票并确认结果
```

Friemi 在此基础上增加适合聚吧的身份与隐私控制：

```text
谁可以投票？
├── 仅聚吧成员
├── 持链接的登录用户
└── 持链接的任何人（含游客）

允许游客时，游客如何署名？
└── 昵称必填
```

核心规则：

1. 默认只有聚吧发起人和管理员可以创建投票。
2. MVP 支持单选和多选；暂不做评分、排序、问答和复杂表单。
3. 投票默认只在聚吧内开放，不会因为创建完成而自动向站外公开。
4. 分享弹层必须让创建者明确选择访问范围，不能默认开启游客投票。
5. 游客必须填写昵称；系统同时使用不可逆标识和限流防止同一浏览器重复提交。
6. 游客昵称不等同于实名，无法可靠证明为“一个自然人”；要求强身份唯一性时必须关闭游客投票。
7. 创建者不能替参与者修改选项，只能删除明显违规的游客票，并留下审计记录。
8. 首张票产生后，问题和选项锁定；需要改变语义时复制为新投票，不能静默改写旧结果。
9. 关闭投票后不可再投或修改；重新开放必须记录操作并通知聚吧成员。
10. 投票分享链接只暴露投票所需信息，不自动开放私密聚吧详情、地址、成员名单或群聊。

## 1. 参考产品与事实边界

### 1.1 标记约定

- **[Doodle 公开]**：Doodle 官方帮助中心明确说明的当前行为。
- **[Friemi 决策]**：为 Friemi 聚吧投票独立制定的产品规则。
- **[验证项]**：逻辑已提出，但上线前仍需通过可用性、安全或压力测试验证。

### 1.2 为什么选择 Doodle

Doodle 的 Group Poll 与 Friemi 当前需求最接近，而不是功能最多：

- 创建者创建投票后通过通用链接邀请参与者。
- 参与者无需 Doodle 账号即可投票。
- 未登录参与者提交时填写姓名和邮箱。
- 参与者可以在投票关闭前修改自己的选择。
- 创建者可以设置截止时间、隐藏参与者和投票详情。
- 隐藏模式下参与者彼此不可见，但创建者仍能查看完整响应。
- 创建者最终选择一个结果并结束投票流程。

以上模式已经覆盖“组内发起、分享出去、游客参与、身份可见性、关闭前修改、最终确认”这条核心链路。Friemi 不复制 Doodle 的品牌、视觉、文案或内部实现，只参考其公开可观察的产品逻辑。

### 1.3 Doodle 公开逻辑摘要

| Doodle 公开能力                      | Friemi 处理                                          | 结论                     |
| ------------------------------------ | ---------------------------------------------------- | ------------------------ |
| 创建者填写标题、说明、地点和候选时间 | 聚吧上下文已提供活动信息，投票只填写问题、说明和选项 | 保留必要字段，减少重复   |
| 通过链接、邮件或聊天工具分享         | 使用系统分享面板、复制链接和二维码                   | 完整覆盖                 |
| 无账号参与者可以投票                 | 创建者开启游客投票后，无账号用户可投                 | 完整覆盖并默认关闭       |
| 无账号参与者提交姓名和邮箱           | Friemi 只要求昵称，不允许留空                        | 降低门槛，不强制收集邮箱 |
| Yes / If need be / No 三态选择       | MVP 使用通用单选/多选；日期协调作为后续扩展          | 泛化到更多聚吧决策       |
| 投票关闭前可修改自己的响应           | 登录用户按账号修改；游客按编辑凭证修改               | 完整覆盖                 |
| 截止后不能提交或修改                 | 截止时自动关闭写入                                   | 完整覆盖                 |
| 隐藏参与者后仅创建者可见姓名和选择   | 首版参与者只看票数，管理员可查看署名票               | 收紧默认隐私范围         |
| 创建者可以删除参与者响应             | 仅允许删除违规票，不允许代改选择                     | 收紧权限以保护可信度     |
| 创建者选择最终时间                   | 创建者可标记最终选项，也可仅关闭不指定结果           | 适配一般投票             |

### 1.4 不应从 Doodle 推断的内容

以下内容不是公开事实，不能照猜或照搬：

- Doodle 的数据库结构、去重算法、风控规则和内部权限实现。
- Doodle 对 IP、设备、Cookie 或邮箱的具体反滥用策略。
- Doodle 的推荐算法、埋点、付费策略和未发布路线图。
- Doodle 的源代码、组件、图标、交互动画和视觉资产。

因此本文采用“公开流程参考 + Friemi 独立领域设计”。

## 2. 产品定位与范围

### 2.1 一句话定义

一个附属于聚吧的轻量决策工具，让成员和受邀游客通过一个链接快速完成单选或多选，并让创建者清楚地控制参与范围。

### 2.2 典型场景

- 大家周末吃什么。
- 聚吧具体几点开始。
- 桌游局下一局玩什么。
- 活动现场购买哪种套餐。
- 多个候选地点中选择一个。
- 收集参与者是否愿意参加附加环节。

### 2.3 v2.8 MVP 范围

- 单选投票。
- 多选投票。
- 2–20 个选项。
- 可选说明和截止时间。
- 聚吧内发布与分享链接。
- 登录用户投票。
- 游客填写昵称后投票。
- 修改自己的投票。
- 实时票数、比例和并列结果。
- 手动关闭、到期关闭、重新开放、取消投票。
- 创建者标记最终结果。
- 分享链接撤销与轮换。
- 基础限流、幂等和审计。

### 2.4 v2.8 非目标

- 不做独立问卷、考试、竞猜或报名表。
- 不做加权票、付费票、排序投票和淘汰赛。
- 不做自由文本答案；说明和意见留在聚吧聊天中。
- 不允许上传图片作为选项，首版仅支持文字和 Emoji。
- 不通过投票结果自动修改聚吧时间、地址或报名状态。
- 不承诺游客昵称与现实自然人一一对应。
- 不允许游客创建投票或管理投票。

## 3. 角色与权限

### 3.1 角色

| 角色         | 定义                                             |
| ------------ | ------------------------------------------------ |
| `ORGANIZER`  | 聚吧发起人                                       |
| `CO_MANAGER` | 聚吧共同管理员                                   |
| `MEMBER`     | 已报名或已确认加入的登录用户                     |
| `LINK_USER`  | 通过分享链接进入、已登录但不是聚吧成员的用户     |
| `GUEST`      | 通过分享链接进入、没有登录的访问者               |
| `SITE_ADMIN` | 网站管理员，仅用于风控和申诉，不参与日常投票管理 |

### 3.2 权限矩阵

| 操作           | 发起人                     | 共同管理员         | 成员       | 链接登录用户   | 游客                   |
| -------------- | -------------------------- | ------------------ | ---------- | -------------- | ---------------------- |
| 创建投票       | 是                         | 是                 | 否         | 否             | 否                     |
| 编辑无票草稿   | 是                         | 仅自己创建或获授权 | 否         | 否             | 否                     |
| 发布与分享     | 是                         | 是                 | 否         | 否             | 否                     |
| 投票           | 是                         | 是                 | 是         | 由访问范围决定 | 由游客设置决定         |
| 修改自己的票   | 关闭前                     | 关闭前             | 关闭前     | 关闭前         | 有有效编辑凭证且关闭前 |
| 查看结果       | 按结果规则，总可见管理数据 | 同左               | 按结果规则 | 按结果规则     | 按结果规则             |
| 关闭/重新开放  | 是                         | 是                 | 否         | 否             | 否                     |
| 删除违规游客票 | 是                         | 是                 | 否         | 否             | 否                     |
| 修改他人的选择 | 否                         | 否                 | 否         | 否             | 否                     |

首版不开放“所有成员均可创建投票”，避免群聊被大量投票卡片占用。后续如有明确需求，可由发起人在聚吧设置中开启成员创建权限。

## 4. 核心状态模型

### 4.1 投票状态

```text
DRAFT -> OPEN -> CLOSED -> OPEN（管理员重新开放）
   |       |        |
   |       |        -> ARCHIVED
   |       -> CANCELLED -> ARCHIVED
   -> DELETED
```

- `DRAFT`：只有创建者和聚吧管理员可见，不接受投票。
- `OPEN`：根据访问规则接受投票和修改。
- `CLOSED`：截止时间到达或管理员手动关闭；只读。
- `CANCELLED`：投票作废，结果不得被显示成有效结论。
- `ARCHIVED`：从活动中的进行中投票列表隐藏，历史仍可查看。
- `DELETED`：仅无投票草稿可以立即删除；已有投票数据的对象进入软删除和保留期。

### 4.2 分享链接状态

```text
ACTIVE -> REVOKED
   |
   -> EXPIRED
   |
   -> ROTATED（旧 token 立即失效，新 token 生效）
```

撤销或轮换分享链接不会删除已经提交的票，也不会影响聚吧成员从聚吧内访问。

### 4.3 选票状态

```text
SUBMITTED <-> UPDATED -> WITHDRAWN
     |
     -> REMOVED_BY_MODERATOR
```

- 同一身份在同一投票中只有一张当前有效选票。
- 修改是更新原选票并增加版本，不产生第二张票。
- 用户主动撤销后可以在关闭前重新投票。
- 管理员删除游客票必须选择原因并留下审计记录。

## 5. 创建投票

### 5.1 入口

投票入口放在聚吧上下文中，不新增底部主导航：

```text
聚吧群聊
├── 输入框“＋”菜单 -> 发起投票
├── 群聊右上角菜单 -> 全部投票
└── 投票发布后 -> 群聊系统投票卡片

聚吧详情
└── 工具区/更多 -> 投票
```

已有“聊天 / 详情 / 公告 / AA”工具条不增加第五个永久按钮，避免小屏拥挤。

### 5.2 创建表单

字段顺序：

1. 问题，必填，1–120 字符。
2. 说明，选填，最多 500 字符。
3. 选项，2–20 个，每项 1–80 字符，不允许规范化后完全重复。
4. 选择方式：单选 / 多选。
5. 多选时设置最多可选数量，默认不限但不得超过选项数。
6. 截止时间，选填；默认不开启。
7. 发布。

### 5.3 默认值

- 默认单选。
- 默认“提交后可看结果”。
- 默认参与者可以看到各选项票数，但看不到具体投票人。
- 默认只允许聚吧成员投票。
- 默认不允许游客。
- 默认不自动选择创建者自己的票。
- 默认不设置截止时间。

### 5.4 发布后的内容锁定

首张有效票产生前，管理员可以编辑问题、选项、选择方式和截止时间。

首张有效票产生后：

- 可以修改说明中的错别字。
- 可以延长或缩短尚未到达的截止时间，但不得把截止时间改到当前时间之前而不确认关闭。
- 可以改变结果展示时机，但不能把已经公开的结果重新伪装成从未公开。
- 不得改写问题语义、选项文字、单选/多选模式或最大选择数。
- 需要改变上述内容时使用“复制为新投票”，原投票关闭或取消。

这样可以避免参与者投给 A 后，管理员把 A 改成另一个含义。

## 6. 分享与游客设置

### 6.1 分享弹层

创建者点击“分享投票”后看到：

```text
分享投票

谁可以通过链接投票？
( ) 仅聚吧成员
( ) 持链接的登录用户
( ) 任何持链接的人（允许游客）

当允许游客时：
游客必须输入昵称

[生成/更新分享链接]
[复制链接] [系统分享] [二维码]
```

分享设置保存到服务端，不能只存在发起人本机。改变设置不需要生成全新投票，但从更开放改为更严格时应提示对已有游客票的影响。

### 6.2 三种访问范围

#### `MEMBERS_ONLY`

- 只有聚吧发起人、共同管理员和已确认成员可以投票。
- 分享链接可以打开投票预览，但非成员会看到“加入聚吧后参与投票”。
- 私密聚吧继续遵守原有好友和邀请规则。

#### `SIGNED_IN_WITH_LINK`

- 任何持有效链接的已登录用户可以投票，不要求先加入聚吧。
- 该权限只作用于投票，不获得聚吧聊天、成员名单、详细地址或报名权限。
- 一账号一票。

#### `ANYONE_WITH_LINK`

- 已登录用户和游客都能投票。
- 游客提交前必须填写昵称。
- 页面必须提示：“游客投票用于快速收集意见，无法严格证明一人一票。”

### 6.3 游客身份

- 游客提交前必须输入 1–30 字符昵称。
- 昵称不是账号，不验证唯一性，也不作为登录凭据。
- 允许同名；界面不得因为重名把两张票合并。
- 创建者看到昵称和一个短游客编号，例如“阿明 · G7K2”。

游客昵称不等同于实名。系统不保存明文 IP、User-Agent 或设备指纹到选票中；清除 Cookie、换浏览器或换网络后仍可能被识别为新游客。需要严格实名或严格一人一票时，创建者必须使用 `MEMBERS_ONLY` 或 `SIGNED_IN_WITH_LINK`。

### 6.5 分享链接安全

- token 至少使用 128 bit 加密安全随机值。
- 数据库只保存 token 哈希，不保存可直接使用的明文 token。
- 链接可撤销、轮换和设置过期时间。
- 分享 token 不复用聚吧私密访问 token。
- 外部页面只返回投票必要字段。
- 私密聚吧默认不显示精确地址、完整成员列表和群聊内容。
- Open Graph 分享卡展示投票问题、Friemi 品牌和截止状态，不展示投票人姓名。

## 7. 参与者投票流程

### 7.1 登录用户

```text
打开聚吧内投票或分享链接
-> 校验投票状态与访问权限
-> 选择选项
-> 提交
-> 服务端幂等写入一张选票
-> 显示“投票成功”与自己的选择
-> 按结果可见规则展示结果
```

- 已有选票时按钮显示“更新投票”，而不是创建第二张票。
- 登录用户的唯一约束为 `poll_id + profile_id`。
- 同一账号跨设备看到同一张票。

### 7.2 昵称游客

```text
打开分享链接
-> 选择选项
-> 继续
-> 输入昵称
-> 提交
-> 获得当前投票专用的编辑凭证
-> 显示成功页
```

- 编辑凭证写入安全、HttpOnly、SameSite Cookie；需要跨 WebView 返回时可同时提供一次性恢复链接。
- 服务端只保存编辑 token 哈希。
- 游客再次从同一设备打开链接时恢复自己的选票。

### 7.3 游客登录后的合并

游客投票后在同一设备登录：

- 如果账号尚未在该投票投过，可以选择“将这张票绑定到我的账号”。
- 绑定后删除游客编辑凭证，选票改由账号管理。
- 如果账号已经有票，不自动合并；提示保留账号票或用当前游客选择覆盖账号票。
- 覆盖必须二次确认，最终仍只保留一张有效票并记录审计事件。

## 8. 选择规则与计票

### 8.1 单选

- 必须且只能选择一个有效选项。
- 修改投票时新选择原子替换旧选择。
- 不允许因网络重试短暂计入两项。

### 8.2 多选

- 至少选择一个选项。
- 最多选择创建者设置的 `maxSelections`；未设置时最多等于选项总数。
- 一张选票对同一选项只能贡献 1 票。
- 总选择次数可以大于参与人数，界面必须分别显示“X 人参与”和“Y 次选择”。

### 8.3 统计口径

```text
参与人数 = 当前有效 Ballot 数量
选项票数 = 选择该 Option 的当前有效 Ballot 数量
选项比例 = 选项票数 / 参与人数
```

多选投票中各选项比例之和可能超过 100%，这是正常结果。界面不得把比例强制归一化。

### 8.4 并列与最终结果

- 票数相同即显示“并列”，不使用提交时间随机破平。
- 系统不自动宣布并列中的某项获胜。
- 创建者可以关闭投票但不标记最终选项。
- 创建者也可以从最高票或任意选项中标记一个最终决定；如果不是最高票，必须填写可选说明并明确显示“由发起人最终决定”。
- 标记最终结果不会修改原始票数。

## 9. 修改、撤销和管理

### 9.1 修改自己的投票

- 仅 `OPEN` 且未过截止时间时允许。
- 登录用户按账号定位选票。
- 游客必须持有效编辑凭证。
- 修改使用数据库事务原子替换选择。
- 每次修改增加版本号并更新时间，但普通结果页只展示当前票。

### 9.2 撤销自己的投票

- 关闭前可以撤销。
- 撤销后不计入参与人数和选项票数。
- 在投票仍开放时可重新提交。
- 关闭后只能查看撤销状态，不能恢复。

### 9.3 管理员处理异常票

管理员可以删除明显的刷票、辱骂昵称或测试票，但必须：

1. 选择原因。
2. 二次确认。
3. 记录操作人、时间、选票 ID 和原因。
4. 重新计算结果。
5. 在管理视图显示“已移除 1 张异常票”。

管理员不得直接把别人的 A 改成 B。需要协助线下参与者时，应创建一个“管理员代录”票并明确标记，不伪装成该用户本人提交；此能力不进入 MVP。

### 9.4 关闭、重新开放和取消

- 到达截止时间后由服务端判断为关闭，不依赖客户端计时器。
- 管理员可提前关闭。
- 管理员重新开放时可设置新截止时间，并通知聚吧成员。
- 已标记最终结果后重新开放，必须先撤销最终结果。
- 取消投票保留历史票数，但结果页显示“投票已取消”，不得继续传播为有效结果。

## 10. 结果可见性

### 10.1 结果展示时机

创建页默认选择 `AFTER_VOTE`：参与者提交自己的票后可见票数和比例。创建者仍可在下拉栏中选择以下其他模式：

| 模式             | 参与者何时可见票数       |
| ---------------- | ------------------------ |
| `AFTER_VOTE`     | 提交自己的票后可见，默认 |
| `AFTER_CLOSE`    | 投票关闭后可见           |
| `ALWAYS`         | 未投票也可见             |
| `ORGANIZER_ONLY` | 仅发起人和共同管理员可见 |

未登录游客在 `AFTER_VOTE` 模式下必须持有效编辑凭证，不能只刷新公共链接绕过提交条件查看结果。

### 10.2 投票人可见性

结果票数与“谁投了什么”必须分开处理：

| 模式                   | 普通参与者                     | 发起人/共同管理员 |
| ---------------------- | ------------------------------ | ----------------- |
| `COUNTS_ONLY`          | 只看票数和比例                 | 可看署名票        |
| `PARTICIPANTS_VISIBLE` | 看署名参与者的昵称与选择       | 同左              |
| `MANAGERS_ONLY`        | 只看自己的选择和允许展示的统计 | 看署名票          |

创建页默认选择 `COUNTS_ONLY`，普通参与者只看票数和比例，不看具体投票人；创建者仍可在下拉栏中调整为其他可见模式。

### 10.3 创建者的可见范围

Doodle 的隐藏投票仍允许创建者看到参与者姓名和选择。Friemi 沿用这一点处理登录用户和填写昵称的游客。

## 12. 通知与聊天联动

### 12.1 发布

- 发布投票后向聚吧群聊写入一条系统投票卡片。
- 对未静音的已确认成员发送站内通知。
- 创建草稿不发送通知。

### 12.2 投票过程

- 默认不为每一张票发送通知，避免刷屏。
- 创建者可以在管理页查看实时参与人数。
- 截止前 24 小时可向尚未投票的登录成员发送一次提醒；投票创建不足 24 小时则不自动提醒。
- 游客没有账号时不发送站内通知。

### 12.3 关闭与最终结果

- 手动关闭、自动截止和重新开放均产生群聊系统状态更新。
- 标记最终结果后通知已投票的登录用户和聚吧成员。
- 游客不要求提供联系方式，因此不承诺离站通知；重新打开分享链接时可看到最终结果。

- 删除异常票。
- 标记或撤销最终结果。

## 14. 服务端动作与事务边界

建议动作：

```text
createActivityPoll
updateActivityPollDraft
publishActivityPoll
updateActivityPollSharing
rotateActivityPollShareToken
revokeActivityPollShare
submitActivityPollBallot
withdrawActivityPollBallot
removeActivityPollBallot
closeActivityPoll
reopenActivityPoll
cancelActivityPoll
finalizeActivityPollOption
archiveActivityPoll
```

每个写操作必须在服务端重新检查：

- 当前用户或游客凭证。
- 投票状态与截止时间。
- 聚吧关系和分享链接权限。
- 选项是否属于当前投票。
- 单选/多选数量约束。
- 幂等键和当前版本。

`submitActivityPollBallot` 必须使用事务完成：

1. 锁定或读取当前投票版本。
2. 判断是否已关闭。
3. 查找当前身份的选票。
4. 创建或更新同一张选票。
5. 原子替换选择集合。
6. 返回服务端重新计算的结果摘要。

客户端传入的票数、参与人数和比例一律不可信。

## 15. 重复投票、限流与风控

### 15.1 登录用户

- 数据库唯一约束保证一账号一票。
- 重复请求携带 `operationId`，网络重试只返回同一结果。
- 修改更新原票，不增加参与人数。

### 15.2 游客

游客去重采用多层弱约束：

- 当前投票专用随机访客凭证。
- HttpOnly Cookie 中的编辑凭证。
- `poll + guestKeyHash` 数据库唯一约束。
- 分享 token、IP 摘要和时间窗口组合限流。
- 异常频率触发验证码或临时拒绝。

不使用侵入式跨站设备指纹。IP 摘要只用于短期限流，不能作为业务身份或长期画像。

### 15.3 产品提示

开启游客投票时明确提示创建者：

> 游客投票适合快速收集意见，无法严格保证现实中的一人一票。重要决策建议仅允许登录用户或聚吧成员参与。

## 16. 缓存、实时更新与性能

- 投票详情可缓存问题和选项，但提交权限和关闭状态必须服务端实时验证。
- 结果更新使用短轮询、Server-Sent Events 或现有实时能力；首版可使用 10–15 秒温和轮询和提交后即时刷新。
- 聚吧列表和群聊预览只返回进行中投票摘要，不加载完整选票明细。
- 结果查询按选项聚合，不能把所有选票传到客户端再统计。
- 外部分享页应可以独立加载，避免请求完整聚吧详情造成性能和隐私问题。
- Redis 只能缓存结果快照和限流信息，数据库仍是最终可信来源。

## 17. 隐私、内容安全与保留

- 游客昵称执行与普通昵称相同的长度、敏感词和控制字符校验。
- 问题、说明和选项使用纯文本展示，不渲染用户 HTML。
- 分享页不展示私人聚吧完整地址和成员头像墙。
- 投票取消或归档后仍按活动历史保留；删除遵循账户和内容保留政策。
- 被管理员移除的票不再参与统计，但审计记录保留最小必要信息。
- 用户账户删除后，署名票按平台隐私政策去标识化；聚合票数可以保留。

## 18. 数据分析

可记录以下不含投票内容的产品事件：

```text
poll_created
poll_published
poll_share_opened
poll_share_link_copied
poll_vote_started
poll_vote_submitted
poll_vote_updated
poll_vote_withdrawn
poll_closed
poll_reopened
poll_finalized
```

分析属性只包含：

- 投票类型。
- 选项数量。
- 访问范围。
- 是否允许游客。
- 来源页面。
- 设备类型。
- 成功/失败类别。

不得把问题文字、选项文字、游客昵称、分享 token 或具体投票选择写入通用分析系统。

## 19. 边界与异常处理

| 场景                     | 处理                                                   |
| ------------------------ | ------------------------------------------------------ |
| 提交时刚好到截止时间     | 以服务端时间为准；拒绝写入并返回已关闭                 |
| 管理员关闭与用户提交并发 | 同一事务版本判断；关闭成功后新票不得进入统计           |
| 选项被修改后旧页面提交   | 发布有票后选项锁定；仍校验投票版本                     |
| 分享链接被轮换           | 旧链接显示已失效，不跳转泄露新 token                   |
| 游客清除 Cookie          | 无法恢复或修改原票；可能被视为新游客，因此显示局限提示 |
| 同一昵称出现多次         | 保留独立票，以短游客码区分；不按昵称去重               |
| 游客申诉自己的票         | 持有效编辑凭证时可撤销或更新                           |
| 聚吧被取消               | 开放投票自动关闭并标记“所属聚吧已取消”                 |
| 聚吧被删除               | 分享链接失效；投票进入删除保留流程                     |
| 创建者退出聚吧           | 管理权转给聚吧发起人或其他管理员，投票不丢失           |
| 私密聚吧投票被分享       | 只开放投票，不开放私密聚吧详情                         |
| 多选比例超过 100%        | 正常展示，并说明为多选投票                             |
| 票数并列                 | 显示并列，不自动按先后顺序破平                         |

## 20. MVP 验收标准

### 20.1 创建与发布

- [ ] 发起人和共同管理员可以创建 2–20 选项的单选或多选投票。
- [ ] 普通成员和游客不能创建或管理投票。
- [ ] 发布后群聊出现一张系统投票卡片。
- [ ] 首张票后问题、选项和投票类型不能被静默改变。

### 20.2 分享与游客

- [ ] 分享弹层支持三种访问范围。
- [ ] 允许游客时昵称必须填写。
- [ ] 未开启游客时，未登录访问者不能提交。
- [ ] 分享链接可以撤销和轮换，旧链接立即失效。
- [ ] 外部分享页不会泄露私密聚吧成员、群聊或精确地址。

### 20.3 投票与结果

- [ ] 登录用户同一投票始终只有一张有效票。
- [ ] 游客重复提交会更新原票，不增加参与人数。
- [ ] 单选只能提交一项，多选遵守最大选择数。
- [ ] 投票关闭前用户可以修改或撤销自己的票。
- [ ] 到期或手动关闭后所有新提交和修改均被服务端拒绝。
- [ ] 多选分别显示参与人数和选择次数。
- [ ] 并列结果不自动产生获胜项。
- [ ] 创建者标记最终决定不会改写原始票数。

### 20.4 游客与管理

- [ ] 游客昵称在创建者管理页中可用于区分选票。
- [ ] 管理员不能修改他人的选项。
- [ ] 管理员删除异常票必须填写原因并产生审计记录。
- [ ] 数据分析不包含问题、选项、昵称或具体选择。

### 20.5 体验与兼容

- [ ] iOS、Android WebView 和移动浏览器均可从分享链接完成投票。
- [ ] 键盘弹出时昵称输入框和提交按钮不被遮挡。
- [ ] 网络失败后保留选项和昵称，重试不产生重复票。
- [ ] App Link / Universal Link 可进入对应投票；未安装 App 时网页仍可投。
- [ ] 不出现弹窗套弹窗。
- [ ] 中文、英文、法文文案均明确提示游客昵称必填。

## 21. 分阶段实施建议

### P0：最小可信闭环

- 聚吧管理员创建单选/多选。
- 聚吧内投票。
- 分享链接。
- 三种访问范围。
- 游客昵称必填。
- 登录一账号一票、游客弱去重。
- 修改、撤销、关闭和基础结果。
- 分享链接撤销、基础限流和审计。

### P1：完整管理体验

- 自动截止与成员提醒。
- 结果展示时机和投票人可见性高级设置。
- 重新开放、取消、归档。
- 最终结果确认。
- 异常游客票管理。
- 游客登录后认领选票。
- App 深链与分享卡优化。

### P2：确认使用价值后再做

- Doodle 式日期/时间三态协调。
- 投票模板和复制。
- 图片选项。
- 排序投票、评分和竞猜。

## 22. 上线前必须确认的产品决策

以下项目本文已给出推荐默认值，产品方仍应在开发前确认：

1. 首版是否仅发起人和共同管理员可创建投票。推荐：是。
2. 持链接的登录用户是否无需加入聚吧即可投票。推荐：允许，但只授予投票权限。
3. 游客是否必须填写昵称。已确认：必须填写。
4. 结果默认何时可见。已确认：提交自己的票后可见。
5. 普通参与者默认是否能看“谁投了什么”。已确认：不能，只看票数。
6. 是否允许用户撤销自己的票。推荐：关闭前允许。
7. 管理员是否可以编辑他人选项。推荐：不允许。
8. 第一版是否加入日期协调三态选择。推荐：不加入，先完成通用单选/多选。

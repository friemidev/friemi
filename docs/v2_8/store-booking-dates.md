# 店铺预约日期：本期实施范围

## 已确认的业务规则

- 每家店铺自行申请开放预约日期，网站管理员审核；审核通过的日期才公开并接受用户报名。不同店铺可以选择同一天，不占用共享场地。
- 预约日历只选择日期，不选择时段。公开信息包括店铺、日期、预约说明和报名人数，不公开报名者身份或联系方式。
- 店铺可从本店已确认的日期创建对应聚吧。一个预约日期最多关联一个聚吧。
- 本期不处理付款，也不把门店优惠券、物品票券与预约混为一条流程。

## 页面层级

| 身份 | 入口和层级 | 主要任务 |
| --- | --- | --- |
| 商家 | 门店管理 → 店铺预约 → 申请日期 / 日期详情 | 提交日期、查看审核状态与报名、从已确认日期创建聚吧 |
| 管理员 | 门店后台 → 店铺预约审核 → 申请详情 | 查看待审申请，确认或拒绝日期 |
| 公众 | 店铺主页 → 店铺预约 → 日期详情 | 看公开日期与报名人数，登录后报名或取消，进入已创建的聚吧 |

## 状态与数据

- 每条日期记录属于一个启用中的门店，保存真实的数据库 `DATE`、标题、公开说明、申请者、审核者、状态和可选的聚吧关联。相同门店同一天只保留一条有效申请；拒绝或取消后可创建新申请，旧记录保留供查阅。
- 日期状态为待审核、已确认、已拒绝、已取消、已创建聚吧。只有已确认和已创建聚吧的日期出现在公开页。
- 每个账号在同一日期只保留一条报名记录；取消后可以重新报名。公开人数只计算当前有效的报名账号，不把商家计入预约人数。
- 提交、审核、报名、取消和创建聚吧都在服务端校验当前身份与日期状态。拒绝必须填写原因；管理员可取消已确认的日期，处理停用或易主门店的申请。并发提交不能产生重复报名或重复聚吧。
- 创建聚吧后，预约入口关闭并指向聚吧；关联聚吧的 `merchantId` 由服务端从当前门店确定，不接受客户端指定。

## 预约转聚吧

- 预约日历始终只选日期。商家在“生成聚吧”页面才填写具体开始时间和真实集合地址；时间先按巴黎时区判断有效性，再按现有本地聚吧的时间格式保存，保证显示与输入一致。
- 该日期已报名的用户自动加入新聚吧，无需重复报名。原预约报名人数与聚吧参与人数分开标注；后者会随新成员加入变化。
- 已发布的预约聚吧不能通过通用编辑页修改日期、地点或公开性。取消聚吧时同步关闭店铺预约日期；删除动作保留预约审计关系。
- 审核通过或拒绝时通知店铺；生成聚吧时通知已报名用户具体时间地点；已确认日期取消时通知报名者，并保留本人日历和原详情链接的取消记录。已生成聚吧的取消沿用聚吧取消通知。

1. 数据迁移、日期校验及角色权限；预览环境核实新增表和迁移记录。

4. 已确认日期创建聚吧；关联、报名转入、重复创建和回跳。
5. 简中、英文、法文，390 px 与 1280 px 视觉和键盘验收；跑类型检查与相关测试。

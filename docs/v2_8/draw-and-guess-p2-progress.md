# 你画我猜 P2 实施与验收记录

更新于 2026-09-29。普通模式的私有增量画笔链路已在 `codex/draw-and-guess` 实现。隔离 Supabase Preview 的数据库、Clerk 身份、私有 Realtime，以及画猜分支 Preview 的五个独立登录浏览器会话，均已完成联调。页面功能与五人完整对局已通过；Preview 另开放双人抢猜供实时体验并完成浏览器回归。原计划明确要求的五台实体设备验收仍需确认，因此 P2 的正式闭环状态以该验收口径为准。普通模式仍只在画猜分支 Preview 开放。

## 已实现

- 每局每回合使用独立私有 topic。Clerk Development 会话令牌带 `role: authenticated`；Supabase Preview 的 Third-Party Auth 只信任该 Development 实例。加入频道时，RLS 验证 JWT 的 Clerk 用户 ID 是否属于当前房间、当前回合和有效截止时间。客户端定期刷新 Clerk JWT 供长连接续订。浏览器没有画笔 INSERT 权限。
- 画者按约 150 毫秒合批发送当前笔画；服务端每批重新检查登录、房间成员、座位、画者、回合与截止时间，再以 Redis 原子序号和每秒 10 批限流。私有画笔使用 `realtime.send(..., true)` 从服务端广播。猜词、答案、分数继续走房间命令。
- 每笔结束保存完整草稿；长笔画每 2 秒保存一次。草稿只确认画者已收到服务端确认的画笔序号，服务端拒绝序号倒退或超前。撤销和清空先等正在发送的批次完成，再保存草稿。重连时先订阅并缓冲批次，再读服务端画作快照及序号，按序号合并后继续接收。旧房间、旧局、旧回合及重复批次被丢弃。
- 房间变更 Broadcast 已连接时，每 10 秒做一次安全快照检查；未连接时每 2 秒轮询，并在重新订阅成功后立即刷新。私有画笔未连接时页面提示正在重连，草稿保存失败时提示并重试。普通模式仅在画猜分支的 Vercel Preview 设置 `DRAW_GUESS_CLASSIC_ENABLED=true`；Production 没有此设置。

## 联调中修复的问题

1. 原有游戏 Realtime 策略调用 `auth.uid()`，会将 Clerk 的 `user_...` 身份强制转成 UUID，私有订阅因此报错。两层现有成员策略改为 `user_id::text = auth.jwt()->>'sub'`，对原有 Supabase UUID 身份保持等价匹配；画猜房间成员仍由单独的严格策略控制。
2. Preview 的 `authenticated` 角色缺少 `realtime.messages` 的 SELECT 表权限，导致读策略无法执行；已补授权。画笔 topic 的 INSERT 仍由限制策略拒绝。
3. Supabase 客户端建立私有订阅前现在显式设置 Clerk JWT，避免初次连接时令牌初始化竞态。
4. 本地根目录测试库连接池设置为 1 时，房间创建的交互事务等待另一个查询并超时。P2 探针仅对自身进程将池上限设为 10，不改线上配置。
5. 原先保存草稿时读取 Redis 最新序号，可能把还未写入草稿的实时批次标记为已包含，造成重连观众跳过笔画。现改用画者的已确认序号；清空和撤销等待当前发送完成后再提交。
6. 入座时房间 `revision` 没有增加，导致房主的 2 秒轮询持续拿到 `304`，直到手动刷新才看见新玩家。入座现在增加版本并发房间变更广播；Preview 的五人入座页面测试无需刷新。
7. 画者保存撤销或清空后，本地画布曾因“保留笔画较多的草稿”规则重新显示旧笔画。现在保存命令完成后读取权威快照，且画者在没有未完成笔画或待保存草稿时应用快照。
8. Dublin 区域切换后的页面回归曾在第一个回合约半程显示画者“正在重连”，尽管画笔 POST 均为 200、观众仍在接收。画笔 hook 现在由频道订阅状态判断是否真正掉线，临时令牌刷新失败不会永久压低连接状态；快照失败会重试，后续发送成功也能恢复发送状态。修复部署后的五人完整页面对局通过原失败步骤并完成第二局到期。

## 验收口径与运行方式

页面验收脚本位于 `apps/web/scripts/probe-draw-guess-p2-browser.mjs`。在 `apps/web` 目录运行 `node --env-file=../../.env.local --conditions=react-server --import tsx scripts/probe-draw-guess-p2-browser.mjs`。脚本只允许隔离 Preview 数据库、Clerk Development 密钥，以及画猜分支 Preview 或本地 3210 端口；默认创建五个一次性测试身份，并在退出时删除测试房间、资料和身份。设置 `P2_BROWSER_PLAYER_COUNT=2` 可运行 Preview 双人完整对局回归；也可设置 `P2_BROWSER_CREDENTIALS_FILE` 复用对应人数的一次性身份，此时身份由提供者负责清理。

原计划的 P2 验收文字为“5 人真实设备对局”。本次证据是五个独立浏览器会话，并未使用五台实体设备或实际移动网络。若继续按原验收文字执行，最后需要五台实体设备复核实时画笔、断线恢复和页面显示；在此之前 P2 软件联调通过，但正式验收未闭环。延迟分位、10 人房与容量预算属于 P3。

实体设备复核使用画猜分支 Preview `https://friemi-git-codex-draw-and-guess-friemi.vercel.app`，由 5 个不同的 Clerk 测试身份在 5 台手机或电脑上打开同一个普通模式房间。记录每台设备的型号、浏览器、网络与所在地区，不在验收记录中存放密码或验证码。五人分别当一次画者：每轮画者持续画至少 3 秒，其他设备在抬笔前应看到新增线条；各轮猜中或到期后，所有设备应看到相同揭晓与最终排行榜。任选一台观众设备中途断网再连接，检查恢复画布与最终作品一致；刷新后再核对一次。将开始/结束时间、断线设备、每项通过或失败及失败时的屏幕录制或截图回填到本记录，方可判定这项实体设备门槛通过。

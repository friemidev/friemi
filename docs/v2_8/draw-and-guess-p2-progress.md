# 你画我猜 P2 实施与验收记录

更新于 2026-09-28。普通模式的私有增量画笔链路已在 `codex/draw-and-guess` 实现，隔离 Supabase Preview 上的数据库、Clerk 身份与五个独立 Realtime 客户端联调已通过。页面端多设备完整对局和断网恢复仍需在最新 Preview 部署完成后验收，因此 P2 尚未宣称闭环，普通模式也不对正式环境开放。

## 已实现

- 每局每回合使用独立私有 topic。Clerk Development 会话令牌带 `role: authenticated`；Supabase Preview 的 Third-Party Auth 只信任该 Development 实例。加入频道时，RLS 验证 JWT 的 Clerk 用户 ID 是否属于当前房间、当前回合和有效截止时间。浏览器没有画笔 INSERT 权限。
- 画者按约 150 毫秒合批发送当前笔画；服务端每批重新检查登录、房间成员、座位、画者、回合与截止时间，再以 Redis 原子序号和每秒 10 批限流。私有画笔使用 `realtime.send(..., true)` 从服务端广播。猜词、答案、分数继续走房间命令。
- 每笔结束保存完整草稿；长笔画每 2 秒保存一次。撤销和清空同步草稿。重连时先订阅并缓冲批次，再读服务端画作快照及序号，按序号合并后继续接收。旧房间、旧局、旧回合及重复批次被丢弃。
- Preview 保留 2 秒房间进度轮询。私有画笔未连接时页面提示正在重连，草稿保存失败时提示并重试。普通模式仅在画猜分支的 Vercel Preview 设置 `DRAW_GUESS_CLASSIC_ENABLED=true`；Production 没有此设置。

## 联调中修复的问题

1. 原有游戏 Realtime 策略调用 `auth.uid()`，会将 Clerk 的 `user_...` 身份强制转成 UUID，私有订阅因此报错。两层现有成员策略改为 `user_id::text = auth.jwt()->>'sub'`，对原有 Supabase UUID 身份保持等价匹配；画猜房间成员仍由单独的严格策略控制。
2. Preview 的 `authenticated` 角色缺少 `realtime.messages` 的 SELECT 表权限，导致读策略无法执行；已补授权。画笔 topic 的 INSERT 仍由限制策略拒绝。
3. Supabase 客户端建立私有订阅前现在显式设置 Clerk JWT，避免初次连接时令牌初始化竞态。
4. 本地根目录测试库连接池设置为 1 时，房间创建的交互事务等待另一个查询并超时。P2 探针仅对自身进程将池上限设为 10，不改线上配置。

## 剩余 P2 验收

1. 等最新画猜分支 Preview Ready，确认普通模式入口和私有连接状态；在真实页面用画者与观众同时操作，观察单笔未结束时笔画出现，并检查撤销、清空和正确/错误猜词。
2. 用独立浏览器会话完成 5 人普通模式全局，包括每人画一次、超时、排行榜及下一局。断线重连后比较观众画布、服务端草稿和最终作品；核对旧回合或跨房画笔不会混入。
3. 5 台实际设备及移动网络体验留作 P2 的最终验收证据；延迟分位、10 人房与容量预算属于 P3。未完成真实设备验收前，只能说 Preview 的私有画笔传输已联通，不能说 P2 全部闭环。

# 斗地主牌桌参考与 UI 改版记录

日期：2026-10-16。对应用户反馈：“看看欢乐斗地主、JJ斗地主的牌桌，牌的间距、叠放，还有摸牌出牌动效，现在的UI不过关。”

## 参考材料与观察

实际查看了 [JJ 官方游戏预览页面](https://ddz.jj.cn/boardgame/ddz.html) 所引用的 [官方视频](https://static.jjbisai.com/website/videos/jj_pcsite/bannerVideo20250624.mp4)，抽取连续帧；同时查看了[腾讯开发者在小米商店提供的欢乐斗地主截图](https://app.mi.com/details?id=com.qqgame.hlddz)。这是对所查展示素材的研究，不代表最新客户端每个版本的实现。

JJ 视频19.50秒的17张手牌约占屏宽93%、屏高30%；单牌约220px宽、相邻起点约98px，露出约45%、重叠约55%。6.00秒选中整组抬高约牌高11%。6.85秒出牌后，余牌居中，桌上牌约为手牌的60–70%。以上是1920×1080帧的人工估测，像素有约5–10px误差。

17.3–18.8秒片段能看到牌背从中上方飞到本人手牌，展开、收拢并整理；6.0–7.1秒能看到选中牌离手、余牌合拢、牌组缩小落桌。视频含特效和剪辑，不能把整个片段长度当作普通动作精确时长。欢乐斗地主的截图支持底部叠牌、左右对手与分区出牌的布局观察；静图不能证明动画时长或手势。

开发参考图和连续帧保存在`output/playwright/doudizhu-references/`，不提交为产品素材。使用原有Friemi猫、SVG牌面与品牌配色，不引入竞品画面、角色或音频。

## 原界面的具体问题

- 手机横屏左右分栏后，手牌只有半屏宽，17/20张牌需要横向滚动，无法一眼判断整手组合。
- 44px独立暴露区被机械地用于所有叠牌，导致牌过疏；表单式白面板又占用空间。
- 角标、选中与桌上牌的比例不够明确，牌的归属和移动方向弱。
- 状态更新主要是替换DOM，缺少“牌从哪来、出到哪去、余牌怎样补位”的连续过程。

## 本次设计决策

| 内容 | 改版要求 |
| --- | --- |
| 牌桌 | 左右对手在上方，本人整手牌在底边，操作浮在手牌上方，当前出牌落点对应出牌者位置 |
| 整手可见 | 根据容器宽度、牌数计算步距；17和20张都能一次看全，少牌收拢居中 |
| 叠牌 | 初始目标露出约40–48%牌宽；20张小屏必要时再压缩，但所有点数、花色和大小王身份必须完整可辨 |
| 触控 | 点选切换，横划连续选牌，松手不出牌；展开网格提供大目标精确选择，主按钮保持44px以上 |
| 选中 | 上抬约12–18px并保留原顺序，不因抬起遮住旁边牌的索引 |
| 补位 | 按卡ID稳定定位，出牌后余牌约160–220ms合拢，少牌不拉伸到全屏 |
| 发牌 | 约700–1100ms；牌背从发牌位置错峰进入三个席位，使用有限视觉对象表现发牌过程 |
| 地主底牌 | 公开的三张牌由顶部底牌区进入地主位置，随后手牌稳定排序 |
| 出牌 | 确认成功后约220–360ms从手牌/对手位置飞至公开出牌位，伴随缩放、轻微倾斜和落桌 |
| 取消 | 切后台、换局、换账号、离房或减少动态时取消在途演出，直接显示有效状态 |

这些时间是Friemi的设计参数，不是对竞品源码的复刻。斗地主没有每回合摸一张的流程，此处“摸牌”具体对应开局发牌和地主领取底牌。

## 验收条件

1. 667×375、844×390和1280×900下，叫分/出牌主要操作与17/20张完整索引均可见；手机竖屏仍进入旋转提示。
2. 中、英、法文案不挤掉倒计时或主按钮；10、大小王、同点数多花色均清楚。
3. 单击、横划、取消、网格展开、键盘以及转屏后选择保持有效，不会自动提交。
4. 完整一局验证出牌后合拢、两次不出交还牌权、结算和返厅；动画不改变任何规则或服务端期限。
5. 用实际新事件捕捉发牌、领取底牌和出牌中间帧；刷新/重连到既有对局不补演历史，减少动态及后台取消有效。

实际通过项目见[实施与验收记录](doudizhu-implementation.md)，真机触感与帧率仍需设备验证。

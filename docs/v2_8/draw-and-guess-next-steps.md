# 你画我猜后续实施计划（P0–P3）

> 基线：`codex/draw-and-guess` 已有两种模式的页面、房间命令和规则状态机。普通模式仍是画完一笔后保存、房间变更通知加 2 秒轮询的体验版。P0 的隔离数据库迁移、5–8 人服务端模拟对局、Preview 独立 5 秒截止扫描，以及 5、6、7、8 个真实 Clerk 身份的独立会话对局均已通过。详细规则见 [双模式设计](./draw-and-guess-two-mode-design.md)和 [P0 验证记录](./draw-and-guess-p0-validation.md)。

P1 的 Preview 证据与剩余发布条件见 [P1 实施与验收记录](./draw-and-guess-p1-progress.md)。真实浏览器会话、故障邮件、管理员审核、保留期清理和压缩后的作品读取均已验证；真机弱网和正式环境资源预算仍按发布条件确认。

P2 已开始实施：私有画笔传输、Clerk 与 Supabase Preview 身份配置，以及五个独立身份的 Realtime 联调通过；页面端和五台实际设备验收尚未完成。见 [P2 实施与验收记录](./draw-and-guess-p2-progress.md)。

## 优先级与发布边界

| 优先级 | 目标 | 完成后可以说什么 | 发布边界 |
| --- | --- | --- | --- |
| **P0** | 接龙在真实房间里从开局走到下一局，且计分、权限、超时可靠 | “接龙功能完成联调” | 仍只在测试环境运行 |
| **P1** | 接龙达到存储、安全、运营和异常恢复要求 | “接龙模式可灰度上线” | 普通抢猜仍标为体验版或仅内部可见 |
| **P2** | 建成普通模式的私有实时画笔链路 | “普通模式已接入真正的画笔 Realtime” | 仍不可宣称达到正式发布性能 |
| **P3** | 压测、移动网络验收和灰度发布普通模式 | “两个模式均达到正式发布门槛” | 根据实测容量控制并发与套餐 |

执行顺序为 `P0 → P1`；P2 的传输开发可以与 P1 并行，但普通模式开放取决于 P3。任何阶段未通过验收，不向后提升发布状态。

## P0｜接龙真实对局闭环

1. **测试环境可运行**：在隔离的测试数据库应用 `DRAW_GUESS` 迁移；核对 Clerk 身份、Prisma 房间、加入码、座位并发占用及 API 授权。正式数据库迁移留到发布流程。
2. **真实多账号对局**：分别用 5、6、7、8 个独立账号与设备完整走一局，覆盖初始词、每轮画与猜、超时补位、全链揭晓、所有人投票、作者选画和排行榜；确认作者从未收到自己链的猜词任务。
3. **服务器独立推进**：补后台到期扫描。全员离线时仍按服务端截止时间推进；任务重复执行、读请求和玩家命令并发时只推进一次、只结算一次。
4. **恢复与结束**：测试断线、换设备、重复命令、过期提交、房主退出和并发猜词；补房主接替与“再来一局”，保留上一局作品和结果只读。
5. **发布隔离**：普通模式设置服务端功能开关和对应入口状态；在 P3 前只允许受控体验，不以“已正式实时”展示。

**P0 验收**：四种人数都能在真实设备上从创建房间走到排行榜，再进入下一局；未授权账号看不到未揭晓词、画或投票；离线和重复请求不改变唯一结算结果。保留对局记录、API/数据库检查结果和失败重试记录。

## P1｜接龙上线质量

1. **持久作品与可恢复快照**：把持续增长的画作与命令结果从单个 `GameToolRoom.state` 拆到有归属和唯一约束的记录；画作同时保存笔画数据与展示图，使用私有存储和按成员授权的读取。设定大小上限、保留期和清理任务。
2. **内容与滥用处理**：给手动词加长度、可见字符和敏感内容校验；给作品与词提供房间内举报、审核记录和频率限制。举报不即时改写已结算分数。
3. **房间通知与降级**：在各环境补齐并验证 Supabase 浏览器公开密钥与房间变更 Broadcast；重连先取本人服务端快照。Realtime 故障时明确提示“正在重连”，轮询兜底但不冒充低延迟实时画笔。
4. **产品与运维收口**：补开局失败、房满、登录失效、草稿保存失败和倒计时到期的可理解提示；记录阶段停留、超时补位、存储失败和重复命令指标，设置告警与回滚开关。

**P1 验收**：测试环境多轮对局、刷新和跨设备恢复后，作品、投票汇总和排行榜一致；权限检查、举报/清理、关键故障告警均通过。随后按小范围灰度发布接龙模式。

## P2｜普通模式真正的 Realtime

1. **私有画笔通道**：为每个回合建立独立 topic，使用可验证的房间成员身份和当前画者权限；非画者只能看，过轮 topic 不能写。若频道权限只在加入时检查，需用可信中继逐批校验或等效机制处理轮次切换。答案、猜词与分数仍只走服务端权威命令。
2. **增量笔画协议**：画者本地即时绘制，将点按约 100–200 毫秒合批；批次带回合 ID 和递增序号，支持撤销、清空与去重。限制点数、字节和发送频率，不把每个触点写入 PostgreSQL。
3. **快照与重连**：定期持久化画布草稿，笔画结束时保存；观众重连时先订阅并缓冲新批次，再取草稿与序号，补齐后继续显示。跨房、旧回合及乱序批次不得混入当前画面。
4. **猜词裁决**：并发正确答案由服务端按接收时间计分；错误答案只反馈本人，正确答案文本直到揭晓才公开。覆盖重复、超时、限频和画者断线场景。

**P2 验收**：5 人真实设备对局中，观众能在画者仍在画一笔时看到增量笔画；断线后画面与最终持久作品一致；无跨房串流、越权发布或答案泄露。此阶段称“已接入画笔 Realtime”，仍不称“可正式发布”。

## P3｜普通模式容量验收与发布

1. **实测场景**：目标地区的真实移动网络分别测试 5 人、10 人、两间同时进行的 10 人房；覆盖弱网、断线重连、画者离线、全部猜中提前结束和多人几乎同时猜中。
2. **量化门槛**：观众画笔可见延迟 **p95 ≤ 300 毫秒**；重连画面与最终作品一致；无丢笔、重复计分、答案泄露或跨房串流。测实际 Supabase 消息量、数据库写入与服务端成本，留出并发余量。
3. **灰度与回退**：按监控结果设置最大并发房间数与批次频率；分批开放普通模式。指标未达门槛时关闭普通模式入口或回到受控体验，接龙不受影响。

**P3 验收**：有可复现的压测脚本、测试报告和监控图；发布期间实际指标持续达标，异常可通过开关回退。此后才对外称两个模式都已完成。

## 当前最先执行的工作包

隔离数据库迁移、多身份模拟对局、后台到期扫描和“再来一局”已通过；画猜分支 Preview 也已部署、迁移，并用 5–8 个真实 Clerk 账号完成独立会话对局。故障邮件、真实管理员审核、保留期清理和压缩后高细节画作容量测量已有 Preview 证据。下一工作包是确认实际套餐容量与灰度规模，并完成真机弱网体验；P1 的测试环境功能验收已经闭环。普通模式的 Realtime 配置、私有频道和容量问题按 P2、P3 验收，不用房间变更 Broadcast 或 2 秒轮询代替。

# 聚吧 AA 简化版：本地审计说明

审计预览：在 `apps/web` 运行 `npm run aa:preview`，打开 `http://127.0.0.1:4174/`。这是正式组件的本地示例数据，不写数据库，也不会向参与者发送通知。预览服务只监听本机，使用与正式 AA 页面相同的组件。示例可切换 €51／过程中已转 €40、€10 三人分、六人多付款人和空账本，并切换成员视角。正式活动入口仍是 `/{locale}/lobby/{activityId}/aa`。

## 这次调整

- 首页突出“我需付／我应收”、总开支、开支与预付款；主持人在“结算明细”发起结算。录入只保留金额、付款人、参与人和可选备注。原有复杂账目的历史金额不重算。
- 首页对因已收预付款而产生的净转出金额显示“预计退还”，结算明细显示“待退还”；其他欠款仍显示“需付／待付”。主持人的首页同时显示“记一笔”和“去结算”，后者先进入明细核对，再发起结算。
- 面向用户的“预付款”统一改成“过程中转账”，入口解释为“先把一部分钱给了某一个人”。记录时只选择“谁转的钱”“转给谁”和金额；它不会增加总开支。技术与历史数据中的记录类型保持原样。
- AA 首页标题改为“记账本”，右侧使用仓库现有的 Friemi 品牌图标；本地预览使用同一图片资源。
- 记账本及其下级页面隐藏底部主导航，底部操作按钮只保留系统安全区间距；Android WebView 与普通手机浏览器使用相同规则。
- 结算进度按当前用户分成“我的待收款”和“我的待付款”。有待收款时可填写本活动的收款方式，结清后仍可修改或移除；保存后，该收款方式只会提供给本人和有对应待付款的参与者。付款人可在待付款卡片及付款详情复制对方填写的内容。
- 新增开支与预付款统一使用 EUR 和整数分。€10 三人分按“付款人优先，再按保存的参与人顺序”得到 €3.34／€3.33／€3.33；付款人不在参与人中时，按参与人顺序分配尾数。
- 预付款作为已发生的转账入账，不增加总开支。已付款结算转账立即入账，不等待收款人再次确认。主持人发起时为所有欠款人生成固定付款安排；其中一笔已付款，不改变其余人的收款对象。
- 收款人标记“未收到”后，争议金额保留在独立的“待核对”区域，不计入待收款或待付款，并暂停继续付款。主持人即使不是这笔付款的双方，也能从首页和结算进度进入核对。核实收到则恢复已付款；核实未支付则撤销该笔金额、作废本轮剩余安排，再重新结算。撤回结算时只作废未付款安排，已付款记录保留。
- 账目写入在数据库事务中校验账本版本、权限和金额守恒，并写审计事件。收款方式属于参与者资料，只能修改本人在当前活动的记录，不改变账本余额。旧入口不能修改简化版的记录或活动中的固定结算安排。既有非 EUR 账本继续走原页面。
- 若收款方还没填写收款方式，付款详情保留活动聊天入口供双方确认；不会展示示例图中的虚拟账号。

## 核对重点

1. €10／3：查看每笔分摊，不应出现按 €0.50 或 €1.00 取整。前端与数据库均保存整数分。
2. €51 示例：总开支 €51、先转的钱共 €40、Lou 需退还 €7；Kevin 应收 €5，Amy 应收 €2。
3. 六人示例：净额为 Lou +€19.23、Kevin +€42.23、Amy −€30.77、Tom −€3.27、Yuki −€23.26、Mike −€4.16。Mike 付 €4.16 后撤回、加入 €18 打车并重新结算时，已付 €4.16 应保留，新安排应为 €36.77、€23.26、€7.97、€1.30。
4. 同一付款按钮重复点击或使用旧版本提交，不得重复计入付款。收款人标记“未收到”后，其余待付款按钮应暂停。
5. 历史账目有待审核、待确认、争议或修改请求时不得发起新结算；历史分摊金额不能被新的均分规则覆盖。
6. 切到收款人视角保存收款方式，再切到对应付款人视角：待付款下方应显示且可复制；不涉及这笔付款的成员不应收到该数据。收款方式按活动账本保存，正式环境需先应用新增数据库迁移。

核算单元测试：在 `apps/web` 运行 `node ../../scripts/run-node-tests.mjs features/aa`。TypeScript 校验：`pnpm --filter @chill-club/web typecheck`。收款方式数据库冒烟测试可在应用全部 Prisma 迁移的隔离本机 PostgreSQL 上运行：设置 `AA_PAYMENT_METHOD_TEST_DATABASE_URL` 后执行 `node --conditions=react-server --import tsx scripts/test-aa-payment-method-db.ts`。该脚本拒绝非本机地址。真实活动账本及线上权限的集成行为仍需在隔离环境审计。

本轮运行 AA 范围的 32 项测试、Web TypeScript 校验和正式构建，包含 10,000 次分摊守恒检查和收款方式可见范围检查。全部 83 个 Prisma 迁移和收款方式数据库冒烟测试已在隔离本机 PostgreSQL 通过；新增迁移也已应用到 Preview 数据库，Production 未更改。浏览器检查覆盖 320px、390px 手机和桌面宽度，以及三人和六人算例中跨成员的收款方式、付款、争议、主持人核对和结清后移除流程；审计截图仅保存在本地，不随代码提交。

产品经理文档中的两条“后台自检”条件并非普遍成立：已经付款金额加新结算金额，不一定等于一次性结算总额（可能产生反向退款）；有预付款或退款时，个人应收也可能高于其自身开支。本实现以逐人净额之和为零、所有份额之和等于开支，以及固定安排全部执行后余额归零为校验依据。

# 骰子多人房间

摇骰子在预览与生产环境都已开放：自由摇骰/三位电脑练习在原页面；「和朋友玩」进入 2–6 人真人房间。游戏大厅中骰子位于 UNO 上方。生产入口页面可被搜索收录，预览页和私人房间不收录。

房主选择人数并创建房间，朋友用房间号加入。房主自动准备，其他玩家准备后房主开局。每人 5 颗骰子；服务端用 `crypto.randomInt` 摇骰并保存房间状态。局内每个人只能看到自己的 5 颗骰子，开盅后才看到全桌骰面。1 点百搭，只能叫 2–6 点；首叫数量至少等于当前人数。同数量必须增加点数，增加数量可以换点。开盅时若实际数量达到叫数，叫点的人得 1 分，否则开盅的人得 1 分。房主可开启下一轮；先得 3 分结束本局，可返回大厅再玩。

房间、座位、成员和事件沿用共享模型；新增 `GameToolKind.DICE` 迁移。骰面保存在服务端房间状态中，数据库 RLS 阻止浏览器权限直接读取或改写骰子房间、座位、成员和事件；只有认证后的房间 API 返回按玩家座位裁剪的快照。快照的缓存标记绑定座位和版本，避免切换玩家时沿用另一人的私有画面。每次命令使用唯一 ID 和当前轮次，数据库 `revision` 条件更新防止同时接受两个动作。写入 API 校验同源请求并限速。Supabase Room Broadcast 只包含房间 ID，客户端接到广播后重新获取自己的快照，另有定期刷新和窗口恢复刷新。离开进行中的房间会取消当前未结束的叫点，剩余玩家重新摇骰；房主离开时转交房主；房主离线超过 60 秒时，在线成员可接任。离开过的玩家可在大厅有空位时重新入座。大厅与结果都可明确离开或结束房间。

这个版本延续原练习版的积分玩法，不设回合倒计时。房间等待离线玩家时可以离开或由房主结束；下一步可按试玩反馈增加倒计时和自动跳过。

# UNO 房间规则与叠加玩法

本次按用户要求在本地实现，未提交或推送。

## 默认及房间设置

| 开关 | 默认 | 行为 |
| --- | --- | --- |
| 罚牌叠加 | 开 | +2 只接 +2，+4 只接 +4，可跨颜色接同类罚牌；不能混叠 |
| +4 挑战 | 关 | 默认可直接出 +4 并指定颜色，不进入挑战等待阶段 |
| 功能牌收尾 | 开 | 允许功能牌及万能牌收尾；关闭后只允许数字牌收尾 |

房主只可在大厅修改规则。更改后清除准备状态；已开始的牌局规则保持不变。加入、离开、返回大厅、下一轮及重新开局保留新房间已选的开关。

## 罚牌及结算

- 接同类罚牌时累加张数并传给下一位。玩家可选择不叠加，摸完累计罚牌后跳过；罚牌回合超时同样处理。
- 若房主打开 +4 挑战，可以选择接 +4、接受罚牌或挑战上一张 +4。挑战成功由上一位摸全部累计罚牌，挑战者继续回合；失败则挑战者摸全部累计罚牌再加二张，并跳过。
- 末张罚牌先让下家摸完累计罚牌，再立即结算，结束叠加链。末张牌不追加等待窗口。
- UNO 宣告和举报继续沿用两张变一张的规则；按钮始终手动可点，无自动提示。下一次有效出牌、摸牌或超时关闭旧的举报窗口。

## 保存与兼容

新规则为 `rulesetVersion: 3`，三个开关及累计罚牌保存在现有房间 state JSON 中，无新增数据库列。结果记录保存该局开关。v1/v2 进行中的牌局保留原规则；未开始的旧房间升级为新默认，界面显示与开局一致。

## 定向复检

- 复现并修复：处于 `CANCELLED` 的房间仍可通过设置请求写回 `LOBBY`。UNO 房间读取统一拒绝关闭状态。
- 复现并修复：读取后、保存前被关闭的房间，若关闭没有增加 revision，旧设置写入会覆盖关闭状态。房间写入的数据库条件同时检查 revision 及非关闭状态。
- 新增实际房间服务的本地模拟检查：重复发送叠加命令不会重复累计罚牌；末张叠加命令重试不会重复摸牌、计分或保存结果；摸牌先提交后，竞争的旧出牌请求被判定为 `STALE_TURN`。

## 继续复检：重进与房间生命周期

本轮未发现新的可复现故障，补充以下实际房间服务的本地回归检查：

- 新玩家加入、退出后重新占座及房主离开移交时，三个规则开关均保留；新加入或重新占座的玩家需要重新准备。
- 进行中的玩家离开并重进，恢复自己的手牌、当前累计罚牌和规则设置，可以继续叠加；新玩家不能中途加入，旧房间链接不能误加入另一个房间。
- 房主掉线后的自动移交保留规则。若房主心跳先于移交事务恢复，移交撤销。
- 返回大厅的事务与另一位玩家心跳恢复竞争时，保留恢复玩家的座位并等待其返回，之后正常建立下一局大厅。
- 开局前的旧设置、旧准备请求不能修改已开始的牌局；使用当前版本的设置请求同样不能在牌局中改规则。

内存模型补齐加入/重进和条件更新，并模拟心跳在读取房间后、事务开始前提交。本轮 `test-uno-settings-local.ts`、98 项 UNO 回归、类型检查及差异格式检查通过。没有连接业务数据库；没有新增界面改动；没有提交或推送。

- 浏览器复现并修复：预设挑战场景在大厅显示挑战关闭，开局却强制开启。明确选择挑战场景时，大厅会显示相应初始设置；用户之后关闭挑战，场景不再覆盖该选择。关闭叠加的挑战场景不保存叠加状态。
- 修复实际 Next 预览页面漏接 `draw-stack` / `wild-stack`：实际页面与静态预览使用同一场景校验入口。

## 其他复检：表情延迟、重试与历史权限

- 内存服务先复现失败用例，再修复：从未被接受的旧表情请求延迟到达下一局大厅时，原服务会接受并显示它。表情命令现在携带发送时的 `matchNumber` / `roundNumber`；服务拒绝过期的新请求，回执哈希同时绑定局数。接口与服务共用严格校验，拒绝缺少局数或计数溢出的请求。
- 已接受的同一表情重试仍返回当前快照，不重复发送，不替换新表情，不重复消耗冷却。修改内容或局数后复用相同 ID、其他玩家复用 ID、离开后重试均被拒绝。
- 历史权限检查通过：离开的参与者可读自己的计分记录；后来复用座位的玩家读不到前任记录。旧的末张出牌命令在原玩家重新加入并换座后，只确认旧回执，不影响新一局状态或计分。历史响应不包含手牌、牌堆、私有令牌、参与者账号列表或挑战依据。
- 本地浏览器加载实际 `UnoRoomClient`，使用合成房间与模拟传输验证响应丢失后的恢复：两次请求的 ID、局数和内容一致，只接受一次；恢复后可继续发送新表情。检查 390 px 手机、1280 px 桌面，无横向溢出、图片加载失败或控制台错误。该浏览器检查没有连接业务数据库或真实服务。

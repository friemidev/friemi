# Friemi UNO 在线游戏：规则与交互方案

> 状态：规则已确认，首版代码与本地验证已完成；尚未迁移真实环境或上线。2026-10-11。实施与验证详见 `uno-implementation.md`。
> 最新确认：举报在最后一张出手前生效；合法数字牌出完立即确定胜负，不设专门举报等待或全员确认。用户已确认宣告宽限与并发裁决、属实举报罚对方摸二张及误报罚本人摸二张。默认采用 500 分积分赛；根据玩家评审改进，房主也可在大厅选择快速单轮。
> 目标：在 Friemi「桌游工具」中提供 2–10 人实时房间对局。参考「你画我猜」的房间体验与系统做法，UNO 规则单独实现。
> 规则基线：[Mattel UNO Card Game 说明书](https://service.mattel.com/instruction_sheets/HPP33-Eng.pdf)。以下“首版决定”是 Friemi 的产品选择；与实体牌说明书不同处均标明。

## 1. 首版范围

| 项目 | 已定规则与首版提案 |
| --- | --- |
| 人数与身份 | 2–10 位已登录 Friemi 用户；房主创建房间，房间号或邀请链接加入。开始后锁定参赛席位。 |
| 牌组 | 108 张基础牌：四色数字牌各 19 张、四色各 2 张「+2 / 反转 / 跳过」、万能牌与万能 +4 各 4 张。实体版说明书另有自定义万能牌；首版不启用。 |
| 发牌与目标 | 每轮每人 7 张；轮流出完手牌者获得其他玩家剩余牌面分。默认累计到 500 分结束整场；快速单轮中首位合法出完者立即结束整场，零分也成立。首轮随机庄家，后续轮次庄家顺座位轮换。 |
| 玩法 | 匹配当前颜色、数字或功能符号；万能牌可自由出。摸一张后只可出刚摸的牌，也可结束回合。允许主动选择摸牌。 |
| 功能牌 | +2 使下家摸 2 并跳过；跳过略过下家；反转改变方向，双人时等同跳过；万能牌出牌时选择颜色；万能 +4 触发挑战窗口。 |
| +4 挑战 | 出 +4 时可故意冒险。下家在 15 秒内选择接受或挑战；服务器以出牌瞬间的手牌校验是否有当前颜色。接受时下家摸 4 并跳过；挑战成功时出牌者摸 4、下家正常行动；挑战失败时下家摸 6 并跳过。服务器只公布裁决，不公开整手牌。 |
| UNO 宣告 | 按用户选择的自定义规则，手里剩 1 张时可随时主动点击始终显示的 UNO 按钮，包括非本人回合。只有符合条件的点击才在本人界面高亮，并向全桌公开一次宣告；其他时候点击不变色。手牌增加至多张则清除标记。漏喊不禁止合法末张出牌；其他人须在出完前自行发现并举报，出完后不再受理。系统不提示漏喊或可举报状态。 |
| 末张限制 | 按用户确定的自定义规则，仅允许四色数字牌 0–9 收尾，且仍须满足颜色或数字匹配。跳过、反转、+2、万能变色、万能 +4 均不能作为最后一张打出。仅剩功能牌时可摸一张并保留，之后在持有至少两张牌时正常使用功能牌。 |
| 牌堆耗尽 | 洗回弃牌堆除最上方一张之外的牌，延续当前颜色。洗牌在服务端执行。 |
| 本轮结束 | 合法数字牌出完即在服务端原子确定赢家、结束本轮并结算；没有被及时举报的漏喊者同样获胜。之后到达的举报失效，不改判。不等待其他玩家确认，不增加额外动画、暂停或倒计时提供举报时间。末张只能为数字牌，因此不存在末张 +2/+4 的罚摸或挑战。计分提案仍为数字按面值、功能牌 20、万能牌 50。 |
| 房规 | 首版关闭叠加 +2/+4、7-0 换牌、抢出、交换手牌和自定义牌。房间页明确展示规则摘要。 |

实体规则没有设备倒计时。为避免在线房间被离线玩家卡住，Friemi 首版建议每回合 60 秒，房主在开局前可选 30/60/90 秒；超时由服务端摸 1 张并结束回合，若正在 +4 挑战窗口则按“接受”处理。超时后抵达的命令一律拒绝。这个倒计时规则属于 Friemi 在线适配，不应写成 Mattel 官方规则。

开局翻到 +2、反转或跳过时按牌面效果决定首位行动者；翻到普通万能牌时由庄家左侧玩家选颜色后行动；翻到万能 +4 时洗回并重翻。双人反转立即让出牌者再行动。双人规则参考 [Mattel 两人 UNO 说明](https://service.mattel.com/instruction_sheets/41764-0920%20uno%20coca-cola.pdf)。

### 待确认的产品取舍

1. 已落实「快速单轮 / 积分赛」房间选项，默认积分赛；开局前由房主选择，变更设置清除全员准备，开局后固定。快速单轮结束后返回大厅重新准备。
2. +4 挑战按实体版的合法性判定，但数字版不向挑战者展示违规者整手牌，降低后续回合的信息泄露。
3. 首版仅限已登录玩家且开局后不补入新人。旁观功能可后加，届时需定义旁观者视图与延迟。
4. 用户已确定末张出手前举报、数字牌收尾、出完立即确定胜负、无举报提示与专门等待。举报入口拟固定放在对手头像菜单内；本方案建议举报属实则被举报者摸 2 张、符合受理条件但对方已喊则举报者摸 2 张。罚牌不跳过或转移当前回合，手牌增加至多张会清除对应宣告。
5. 宣告宽限采用下述自然行动边界，不暂停牌局、不增加确认步骤。这是为补齐刚剩一张时的宣告机会而提出的具体方案；它减少立即抢报，但不保证网络或反应速度完全公平。
6. 将举报放在牌局结束前并对误报罚牌，可让误报影响后续胜负，但仍不能保证消除所有盲报策略；不得把“没有系统提示”表述成“必然依赖观察与记忆”。

### 宣告与举报的完整收尾规则

1. **刚剩一张**：从多张变为一张时开启新的一张手牌阶段，并进入宣告宽限。该玩家可在任何人的回合点击 UNO；导致自己刚剩一张的动作不同时结束自己的宽限。
2. **自然开放举报**：在上述动作之后，第一次成功出牌、主动摸牌或普通回合超时代摸完成时，若本轮仍继续、目标仍剩一张，宽限结束。动作可来自任意座位，包括目标本人；完成动作包含其立即产生的强制效果。UNO、举报、选牌、无效请求、+4 接受/挑战和其自动处罚都不单独结束宽限。没有专用计时器、提示或停顿。
3. **举报成立**：宽限结束后，目标仍剩一张且尚未宣告，其他参赛者可举报。建议目标摸 2 张，已出的牌保留，按原方向和当前回合继续。若目标已宣告，符合其他受理条件的举报按误报处理，建议举报者摸 2 张。宽限内、跨轮次、目标已不剩一张或本轮已结束的举报仅作无效请求，不处罚。
4. **主动宣告**：在末张出手前均可点击 UNO，包括已经开放举报时；若宣告先被服务端接受，后续举报不能成立。宣告、举报和出牌按服务端成功提交的顺序判定；不声称按玩家本地点击时间判定。已宣告后才受理的有效格式举报属于上项误报，网络竞速也按同一顺序处理。
5. **出完与并发**：合法数字牌出完先成立，则本轮立即结束，随后举报失效；举报先成立，则目标已增加手牌，基于此前手牌版本发出的末张出牌请求作过期处理，玩家按新状态继续操作。成功末张出牌不会给其他玩家再加一次操作机会。
6. **重置与去重**：任何原因使手牌超过一张，都结束当前一张手牌阶段并清除宣告；下次降至一张重新开始。举报绑定轮次和该阶段，网络重试不重复罚牌；同一目标同一阶段的属实举报仅生效一次，同一举报者对同一目标同一阶段的误报也只处罚一次。重复、过期或已处理请求不重复处罚。
7. **连续行动边界**：双人跳过/反转后，如果该玩家下一次行动就是合法数字牌出完，直接获胜，不为补足举报机会暂停。这属于漏喊未被及时抓到的允许结果。

## 2. 对局状态与命令

```mermaid
flowchart LR
  A[房间等待 / 准备] --> B[发牌与翻起始牌]
  B --> C[玩家回合]
  C -->|出牌后仍有手牌| C
  C -->|摸一张| D[仅可出刚摸牌或结束]
  D --> C
  C -->|万能 +4| E[接受或挑战]
  E --> C
  C -->|出完前有效举报：罚摸并继续| C
  C -->|合法数字牌出完| F[立即确定赢家并结算]
  F -->|积分赛且无人达 500 分| B
  F -->|单轮赛或达到 500 分| G[整场结果]
  G --> A
```

- 服务端状态至少记录：规则版本、座位与庄家、轮次、方向、当前玩家、回合 ID、牌堆顺序、弃牌堆、有效颜色、各人手牌与手牌版本、分数、截止时间、待处理罚摸/挑战、UNO 宣告、一张手牌阶段 ID、该阶段起始动作序号、宣告宽限是否结束、举报处理记录、最近动作摘要。牌用稳定唯一 ID 标识，同点数牌也不能混淆。举报资格及宽限状态仅在服务端保存，不向对手快照提供可举报布尔值。
- 命令建议为 `READY`、`START`、`PLAY_CARD`（万能牌同时提交颜色）、`DRAW_CARD`、`PLAY_DRAWN_CARD`、`PASS`、`ACCEPT_DRAW_FOUR`、`CHALLENGE_DRAW_FOUR`、`CALL_UNO`、`CATCH_UNO`、`REMATCH`、`RETURN_TO_LOBBY`。每个写命令有 `commandId`、整场/轮次/回合 ID，重试沿用原 ID。
- 摸牌后只允许刚摸的那张牌出在当前回合；已持有牌不可再出。出牌时服务器校验所有权、颜色/数字/符号、待处理罚摸、当前座位和截止时间，并拒绝会以功能牌清空手牌的出牌请求；拒绝不会消耗回合或移走牌。+4 合法性以出牌前的手牌快照判断，不依赖客户端声明；+4 不可能成为合法末张。
- `CALL_UNO` 只在本人剩 1 张、本轮进行中且末张尚未出牌时生效，不要求轮到本人，绑定当前一张手牌阶段。若点 UNO 后紧接出牌，客户端按顺序提交并等待本人宣告命令回执，服务端以成功提交顺序判断；这不暂停其他玩家的操作，也不要求其他人确认。末张出完后不再接受补喊或举报。
- 每次成功的常规行动提交时先判断合法末张是否结束本轮；若未结束，再为此前已存在且仍持一张牌的阶段结束宣告宽限。该动作新产生的一张手牌阶段保留宽限。自动处罚、挑战结果和其他非正常行动不单独触发宽限结束。
- 举报使用轮次、一张手牌阶段 ID 和 `commandId` 校验，不采用固定秒数的窗口。所有对手的举报控件保持相同入口与样式；不公开 `canReport`、漏喊标记或举报窗口提示。属实举报原子执行一次罚摸；同一举报者的同阶段误报去重。过期、网络重试和已处理请求不得再次处罚，未生效结果仅反馈操作者。
- 宣告、举报、出牌和结算均由服务端排序并原子提交。数字牌合法清空手牌的同一事务写入本轮结束、赢家和积分；后续举报无法改写结果。举报导致手牌变化后，旧手牌版本的出牌命令不自动重放，避免把玩家想提交的末张改为另一种出牌结果。
- 发牌或回合结算可重复调用但只写一次；房主手机断开或所有人离线也不影响服务端推进。

## 3. 页面与交互

### 入口与大厅

- 在现有「桌游工具」卡片列表加入 UNO。入口首屏直接展示“创建房间 / 房间号加入”，人数和经典规则摘要；支持中文、英文、法文。
- 大厅沿用画猜的轻快纸面、圆角厚底主按钮、明确焦点和状态反馈。座位区显示头像/昵称、房主、准备、空位；房主可设置回合时长并开局。邀请链接与房间号随手可复制。
- 开局条件为 2–10 位真人全部准备。房主退出或失联按既有房间接任模式处理。开局后离线者保留手牌与座位，返回时恢复；服务器按规则超时自动代摸、过牌。

### 对局桌面与手机

| 区域 | 手机 | 桌面 |
| --- | --- | --- |
| 顶部 | 返回/房间号、轮次、当前玩家、方向、倒计时的紧凑栏 | 同信息置于桌面上沿，留出稳定桌面空间 |
| 对手 | 小头像、剩余牌数、准备/掉线提示；不显示牌面 | 围绕牌桌分布，牌数和当前行动者明显 |
| 中心 | 摸牌堆、弃牌堆、当前颜色、最近动作和目标指引 | 更大的牌桌和动作回放，仍只保留一个主操作 |
| 我的手牌 | 屏幕下方横向可滚动扇形或单排；数字、颜色和符号并用 | 展开显示，键盘可逐牌聚焦 |
| 操作 | 上方固定三个按钮“不出 / UNO / 出牌”，位置与顺序始终一致。点牌先选中，再点出牌；万能牌先选颜色再提交。 | 同样保留三个固定按钮，支持键盘选牌与确认 |

- 仅自己的牌显示正面，其他座位只显示牌背和张数。可出的牌有轻微抬起与描边；不可出的牌保持清楚可读，但说明原因。不能只靠颜色辨认四种牌，给颜色配固定图形或文字标签。
- “不出”在未摸牌时摸 1 张；摸后若该牌不可出则自动结束回合，若可出则再次点“不出”结束回合，同一回合不能反复摸牌。UNO 按钮不随手牌张数自动变亮或闪动；本人剩 1 张并主动点击成功才高亮。成功宣告向全桌短暂展示一次“UNO！”，漏喊没有声音、文字或图标提醒。
- 仅剩一张功能牌时，该牌不能打出，并以普通出牌校验反馈说明“最后一张须为数字牌”。玩家仍可点“不出”摸一张，即使摸来的牌可出也能保留并结束回合；之后轮到本人时可在至少两张手牌的情况下出原功能牌。摸牌不会立即解锁同回合打出原有牌。
- 点任意对手头像的常驻菜单可选择“举报漏喊 UNO”。所有对手的菜单入口和样式始终相同，不因有效举报机会而新增、高亮、闪动、显示角标或改变禁用状态。规则页说明该操作位置，对局中由玩家自己观察、记忆和判断；未成功的举报仅给举报者普通结果反馈。
- 末张出牌不增加举报等待、结算确认按钮或全员确认步骤，不以延长落牌动画来提供举报时间。常规动画不决定举报受理边界；服务端已接受合法末张时，即使其他设备仍播放动画，该轮举报也已失效。
- +4 只给受罚者显示“接受摸 4 / 挑战”决策层；其他人看到等待状态。挑战结果以短动画和文字解释罚摸归属，不展示整手牌。
- 断线时保留当前桌面并显示“正在重连”；恢复后先拉本人快照，再开放下一次操作。网络失败和命令过期都有可理解提示，不假装本地出牌已成功。
- 按画猜的移动端经验检查安全区、动态视口、短屏、横屏及底部导航遮挡。触控目标至少 44 px，输入/弹窗有键盘焦点，尊重减少动态效果设置。声音可开关。

### 结算与回房

- 每轮展示赢家、其他玩家剩牌计分、累计分和下一轮庄家。达到 500 分后展示整场排名、关键动作摘要与再来一局。
- 对局历史只向本场参赛者开放；记录赢家、各轮积分、参赛名单和规则版本。历史不泄露仍可能影响未来局的私密手牌或洗牌顺序。
- 玩家各自选择返回大厅；人数未齐时显示等待与进度。下一局准备状态重新清零。

## 4. Friemi 系统接入

- 新增独立 UNO 规则引擎及测试，不向 `drawGuessEngine.ts` 增加 UNO 分支。复用 Clerk → `UserProfile` 身份、房间号、座位/成员、邀请与已有游戏工具入口约定。接入点包括 `gameToolCatalog.ts`、`gameToolRooms.ts`、`GameToolKind`、本地化路由和 API。
- `GameToolRoom.state` 可保存首版规模的权威牌局 JSON；只允许服务端读取原始值。新增 UNO 截止时间索引、命令去重记录和只读轮次历史；避免复用 `drawGuessDeadlineAt` 或画猜作品表。后续若牌局记录扩大，再拆分存储。
- 写命令做身份、房间席位、回合与牌所有权校验；在数据库事务中用 `revision` 比较更新并记录 `commandId` 唯一结果。并发请求重试读取新状态；同一命令不会重复摸牌、计分或跳过。
- Realtime 只广播“房间版本更新”通知，客户端据此拉取**本人视角**快照；焦点恢复和低频轮询兜底。公开消息不能携带整副牌、任何手牌或牌堆顺序。服务端独立截止扫描推进超时回合与 +4 决策。

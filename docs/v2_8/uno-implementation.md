## 服务端与数据

- 独立 `unoEngine.ts` 规则引擎；`unoRoomServer.ts` 负责成员、房主、准备、持久化与本人视图。
- 房间 `GameToolRoom.state` 仅供服务端读取。响应只包含请求者手牌、其他人的张数、公开牌面与公开事件；不提供其他人的手牌、持续宣告标记、举报资格、宽限状态或洗牌顺序。
- 每次命令提交在数据库事务内比较 `revision`，写入状态与 `UnoCommand` 回执；重复命令绑定原操作者、完整请求摘要与场次/轮次。发生冲突最多重试 6 次。
- 服务端洗牌使用 `node:crypto` 随机数。客户端不能提交牌堆、座位身份、积分或惩罚结果。
- 合法末张及末张罚摸、赢家、积分与 `UnoRound` 历史原子写入；举报无法改写已完成的结果。
- 真实用户开局，2–10 人全部准备。开局后席位锁定；离开者保留手牌，同时释放共享的“正在游戏”占用；重新加入同一房间恢复手牌与在场状态。
- 房主离开时交接；房主超过 60 秒未出现后，活跃成员拉取房间时可接任。大厅超过 90 秒未出现的成员被移出；对局中保留席位并按正常回合超时处理。
- 结束后每人通过 `/return` 返回，仍在线成员都返回才重置大厅；准备清零、场次编号增加。离线成员不阻塞返回；移除离线席位时在事务内重新校验心跳，避免丢掉正在重连的玩家。直接 `REMATCH` 拒绝并返回 `RETURN_TO_LOBBY_FIRST`；有人选择返回大厅后，`NEXT_ROUND` 同样拒绝，避免把已经返回的人拉入新一轮。
- Realtime 只广播房间 ID 与 revision；浏览器收到消息后重新请求本人快照。轮询作为兜底。
- 猫咪角色复用画猜 `drawGuessCats.ts` 的角色 ID、校验与确定性默认值，保存在已有 `GameToolSeat.roleKey`，不新增数据库迁移。创建/加入时保存默认角色，旧数据缺失或失效时按房间 ID 与座位生成稳定角色。角色为公开信息；选角只允许本人在大厅进行，使用与开局相同的 revision 事务，因此不会在开局后改角色。纯外观修改不清空准备。
- 大厅房主可选择经典积分 `score` 或快速单局 `single`；新房默认经典积分。规则设置实际变化时清空全员准备，加入/离开/返回大厅保留模式，开局后禁止修改。旧状态没有模式字段时按经典积分处理。
- 主动猫咪表情只有 `laugh/applause/surprise`，在大厅、进行中与 +4 挑战时可发。每席位只存最新表情，显示 4500 ms，冷却 3000 ms；表情保存在房间 config，复用命令回执防重试重播，不写规则 events、不修改回合/截止时间/宣告宽限。结束后不发送。表情均由玩家主动触发，不形成 UNO 或举报提示。

## API

统一前缀：`/api/game-tools/uno`。要求 Clerk 已登录且 `UserProfile.status = ACTIVE`；UNO 写接口不使用匿名开发身份降级。所有写请求校验同源 `Origin`，并带每用户频率限制；已有 Redis 频率限制启用时同时使用分布式计数，本地内存限制作为单实例兜底。

| 路径 | 方法 / 请求 | 结果 |
| --- | --- | --- |
| `/rooms` | POST `{ locale, turnSeconds?: 30/60/90 }` | `{ roomId }` |
| `/join` | POST `{ code, expectedRoomId? }` | `{ roomId }`；恢复原房间时绑定 ID，防止房间号重用 |
| `/rooms/:id` | GET | `{ room }`，私有且禁止缓存 |
| `/rooms/:id` | PATCH `{ expectedRevision, turnSeconds?, matchMode? }`，设置至少一项 | `{ room }`；房主、大厅限定，规则变化清除准备 |
| `/rooms/:id/ready` | POST `{ expectedRevision, ready }` | `{ room }` |
| `/rooms/:id/character` | PATCH `{ expectedRevision, catId }` | `{ room }`；本人、大厅限定，沿用画猜角色 ID |
| `/rooms/:id/reactions` | POST `{ reactionId: UUID, kind: laugh/applause/surprise }` | `{ room }`；本人主动表情，20 次/分钟、3 秒冷却 |
| `/rooms/:id/actions` | POST 命令信封，见下 | `{ room }` 或 `{ error }` |
| `/rooms/:id/leave` | POST `{ expectedRevision }` | `{ ok: true }` |
| `/rooms/:id/return` | POST `{ expectedRevision }` | `{ room }`，包含返回进度 |
| `/rooms/:id/history` | GET | `{ rounds }`，只返回请求者实际参加的历史分数摘要 |

命令信封为 `{ commandId, matchNumber, roundNumber, turnId, action }`。`commandId` 网络重试必须复用；不同操作必须产生新 ID。动作包含 `START`、`PLAY`、`DRAW`、`PASS`、`CALL_UNO`、`CATCH_UNO`、`CHOOSE_COLOR`、`ACCEPT_DRAW_FOUR`、`CHALLENGE_DRAW_FOUR`、`NEXT_ROUND`。

准备、设置、选角、退出和回房使用发起时的 `expectedRevision`；房间版本变化后返回 `STALE_COMMAND`，每次数据库 CAS 重试也重检。没有持久回执的请求若结果不明，只刷新当前快照，不自动重发旧意图；用户重新点击产生新请求。出牌命令与表情有去重回执，可以保持原 ID 重试。

- `PLAY` 附 `cardId`、`handVersion`；万能牌附 `color`。
- `CALL_UNO` 附本人 `episodeId`、`handVersion`；任意手牌数量和其他人的回合可宣告，校验场次、轮次及手牌版本。v1 兼容缺少版本字段。
- `CATCH_UNO` 附 `targetSeat`、目标 `episodeId`、`roundNumber`；不会根据是否有效改变菜单入口。
- `START`、`NEXT_ROUND` 仅房主可操作。`NEXT_ROUND` 延续同一场积分，整场结束后必须经过返回大厅与重新准备。

`room` 包含 `id/code/revision/serverNow/hostSeat/viewerSeat/seats/state/returnedToLobby/reactions`。`serverNow` 为生成快照时的服务端毫秒时间戳；客户端以此配合单调时钟计算倒计时与表情到期，避免设备时间不准或被修改造成异常。重复、旧快照和延迟到达的新时间样本不会让倒计时倒退；缺少该字段的本地练习与旧夹具仍使用本地时间。座位 ID 从 0 开始且可不连续；每个 seat 含 `name/avatarUrl/catId/ready/connected/returned`。选角接口要求同源、登录成员身份，每用户每分钟最多 30 次；非法角色返回 `INVALID_CHARACTER`，开局后返回 `WRONG_PHASE`。

`room.reactions` 始终为数组，只含尚未过期的 `{ id, seat, kind, createdAt, expiresAt }`。时间为服务端毫秒时间戳；座位由登录成员推导，接口不接受代别人发送。重试保留相同 reactionId；已成功但过期的表情不会再次播放。不同表情在冷却内返回 `REACTION_COOLDOWN`，非法内容返回 `INVALID_REACTION`。Realtime 仍只广播版本通知。

# v2.6 关系系统调整 Checklist

## 目标

Friemi 暂时收起传统“好友申请 / 接受申请”的关系模型，改为更轻的关注关系。

用户之间的关系由关注产生。双方都关注彼此时，视为互相关注。互相关注承接原“好友”承担的核心权限，但站内关系文案优先使用关注关系。

## 关系定义 Checklist

- [x] 关注：我关注了对方，对方没有关注我。
- [x] 被关注：对方关注了我，我还没有关注对方。
- [x] 互相关注：双方都关注彼此。
- [x] 他人主页按钮状态支持：关注、已关注、回关、互关。
- [x] 用户搜索和头像预览使用统一关注状态。
- [x] 个人主页关系列表完整拆分为：我关注的、关注我的、互相关注。
- [x] 世界聊聊筛选器完整拆分为：聊聊、我关注的、关注我的、互相关注、群聊。
- [x] 聚吧原“好友权限”切换为“互相关注权限”。

## 文案策略 Checklist

- [x] 主要用户路径不再出现“加好友 / 好友申请 / 接受申请 / 拒绝申请 / 删除好友”。
- [x] 搜索、Profile、用户预览弹窗使用“关注 / 已关注 / 回关 / 互关”。
- [x] 消息入口的“添加好友”改为“找人”。
- [x] 通知中心不再内联处理好友申请。
- [x] Profile 统计和入口统一改为：关注、关注我的、互相关注。
- [x] 旧“好友号”在主要关系路径中改为“Friemi ID / 个人码”。

说明：“好友”不是完全禁词。对外解释网站时，如果“好友”更容易被新用户理解，可以保留，例如“和好友一起参加活动”。站内关系系统、权限、按钮和筛选器优先使用关注关系。

## 私聊规则 Checklist

- [x] 私聊发送策略从 `isFriend` 切换为 `isMutualFollow`。
- [x] 互相关注可以正常私聊，不限制消息数量。
- [x] 非互相关注在对方回复前最多发送两条消息。
- [x] 对方回复后，本次对话可以继续进行。
- [x] 自己不能给自己发消息。
- [x] 信用过低用户仍可能被限制发起陌生私聊。
- [x] 用户侧提示保持轻量：还可以发送 2 条、等对方回复后继续聊。

## 世界 · 聊聊 Checklist

- [x] “聊聊”承接私聊和聚吧群聊入口。
- [x] 聊天未读红点只计算实际未读消息。
- [x] 非互关用户发来的已有消息在总列表可见。
- [x] 筛选器调整为：聊聊、我关注的、关注我的、互相关注、群聊。
- [x] “我关注的”展示我关注的人。
- [x] “关注我的”展示关注我的人，右侧提供回关按钮。
- [x] “互相关注”展示双方互关的人。
- [x] “群聊”展示聚吧群聊。

## 聚吧权限 Checklist

- [x] 仅好友可见 -> 仅互关可见。
- [x] 好友可报名 -> 互关可报名。
- [x] 好友也在 -> 你关注的人也在。
- [x] 好友发起 -> 你关注的人发起。
- [x] 好友参加 -> 你关注的人参加。
- [x] 协管、私人聚吧、熟人局优先使用互相关注判断。
